### 0.1 术语表

| 术语 | 定义 |
| :--- | :--- |
| 渠道（Channel / Provider） | 数据来源方。首发五项：`claude`、`codex`、`workbuddy`、`gemini`、`custom`（自定义只读探针）。`workbuddy` 为必选交付。 |
| 账号（Account） | 一个渠道下的一份授权 + 一组额度快照。本地主键 `account_id`（UUIDv7）。 |
| 窗口（Window） | 一个有重置周期的额度池（5h / 1w / 日 / 积分池）。 |
| 快照（Snapshot） | 某次成功探针返回的归一化结果，含 `last_synced_at`。 |
| 探针（Probe） | 一次只读 HTTP 请求，仅取用量，不写上游、不消耗额度。 |
| 主窗口 / 副窗口 | 决定菜单栏与卡片主数字的窗口（主）/ 辅助窗口（副）。 |
| 周期键（period_key） | `(window_label, reset_at)`，用于“同一周期只告警一次”与“重置后清零”判定。**派生值**：每次由快照计算，不落库、不对外暴露字段名，界面只说“周期已更新 / 周期未变”。 |
| 最后已知值 | 最近一次 `Normal` 快照的数值。只允许带"最后已知"前缀展示，不得单独出现。 |
| 单飞（single-flight） | 同一 key 的并发请求合并为一次，其余调用方复用同一结果。 |

### 0.2 屏 ID 规则

| 形态 | 含义 | 示例 |
| :--- | :--- | :--- |
| `F<n>-S<k>` | 第 n 条流程的第 k 个屏 | `F2-S5` 设备配对码 |
| `F<n>-S<k>·V<m>` | 同屏的第 m 个状态变体（不新增屏） | `F3-S1·V4` 单卡 429 变体 |
| `EX-S<k>` | 异常/边界专用屏（跨流程复用） | `EX-S2` 401 失效 |
| `SYS-<k>` | 系统级界面（菜单栏图标、系统通知横幅），非面板内屏 | `SYS-1` 菜单栏 |

屏清单见 §2；原型必须至少实现 **P0（28 屏）**，建议全量 50 屏。

## 1. 全局规则引擎（所有流程共用）

### 1.1 数据语义：缺失 ≠ 零

| 字段 | 类型（归一化后） | 缺失语义 | 禁止写法 |
| :--- | :--- | :--- | :--- |
| `remaining_percent` | `Option<f64>` / `number 或 null` | `None` = 未知，不可推断 | `unwrap_or(0.0)`、`?? 0`、`Number(x)` 后兜 0 |
| `total_amount` | `Option<f64>` | `None` = 上游未给总量（积分制常见） | 用 `used` 反推总量 |
| `used_amount` | `Option<f64>` | `None` = 未提供 | 用 `100 - remaining` 伪造；`total_amount` 为 `None` 时也不得由 `remaining` 反推 |
| `reset_at` | `Option<i64>`（Unix 秒，UTC） | `None` = 无重置（积分池/无窗口） | 填 `now + 5h` 之类的猜测 |
| `last_synced_at` | `Option<i64>` | `None` = 从未成功（`NeverSynced`） | 填启动时间 |
| `state` | `AccountHealthState`（7 值，见 §12；与 ARCHITECTURE §3.5、`core/src/domain/types.ts:165` 三处一致） | 必填，无默认值 | 默认 `Normal` |

数据库列全部 nullable；序列化层禁止 `#[serde(default)]` 给数值字段兜 0。

**派生列口径（M-01）**：详情窗口表只在 `total_amount` 有值时渲染「已用」列，并在表头标「推导」；`total_amount` 为 `None` 时整列不渲染
（不是显示 `—`，是列级隐藏，避免把一个反推值摆成和实时值同等可信的位置）。静态检查：内核 CI 禁止出现 `unwrap_or(0`、`unwrap_or_default()` 作用于额度字段（见 A02）。

### 1.2 百分比可渲染判定（Render Gate）

只有同时通过 G1–G6，才允许在界面出现彩色百分比与实心圆环弧：

| 门 | 条件 | 不通过时 |
| :--- | :--- | :--- |
| G1 | `state == Normal` | 走 §1.3 状态文案，数值区显示最后已知值（灰色，带"最后已知"前缀）或 `—` |
| G2 | 目标窗口存在（`primary_window` / `secondary_window` 非空） | 该行不渲染，显示"本渠道无此窗口"灰字（不占百分比位） |
| G3 | `total_amount` 存在且 `> 0` | 该窗口降级为绝对值展示（如 `4,200 积分`），不出百分比 |
| G4 | `remaining_percent` 为 `Some(p)` 且 `0 ≤ p ≤ 100`（含端点） | 越界即判定 `ParseDegraded`（E32），数值区 `—` |
| G5 | 数值非 `NaN` / `Inf` | 判定 `ParseDegraded`，数值区 `—` |
| G6 | `mono_elapsed(last_synced_at) ≤ stale_ttl`，`stale_ttl = 2 × T_base + 60s`（默认 660s）。`mono_elapsed` 取 **单调时钟**（`mach_continuous_time` / `CLOCK_MONOTONIC`）的差值，墙钟只用于展示 `{HH:mm}` | 判定 `OfflineStale`（数据过期），文案转“离线”；唤醒宽限期内（T-wake）不判离线，呈现为“恢复中” |

```
resolveDisplay(account, window) -> DisplayValue
  if account.state != Normal            -> Stale(last_known=snapshot_of_last_normal)
  if window == nil                      -> Hidden
  if total == nil || total <= 0         -> Absolute(used, unit)
  if p == nil || p.isNaN() || p < 0 || p > 100 -> Degraded
  if mono_elapsed(last_synced_at) > stale_ttl   -> Stale(last_known)
  else                                  -> Percent(p, color=ringColor(p))
```

`0%` 的唯一合法来源：`state == Normal && p == Some(0.0)`，且文案必须追加"已耗尽 · {reset} 重置"。任何推算、缺失、异常都不得落入 0。

> **「最后已知值」不是「当前百分比」**：它必须同时满足三个形式条件——① 带「最后已知」前缀、② 灰化且不参与语义色（绿/黄/红）、③ 不进入圆环弧。三者缺一即视为违反规则 1。这也是 `A01` 断言的判定口径。

### 1.3 状态文案词表（界面唯一文案来源）

| 状态 | 主文案（≤6 字） | 副文案（≤14 字） | 数值区 | 圆环 | 语义色 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `Normal` | （不显示状态词） | `{HH:mm} 更新` | `62%` 实色，等宽 | 实心弧（剩余长度） | 绿 / 黄 / 红（按剩余） |
| `Normal` + 耗尽 | `额度已耗尽` | `{HH:mm} 重置` | `0%` 红色 | 空环（仅轨道） | 红 |
| `OfflineStale` | `离线` | `{HH:mm} 最后同步` | `最后已知 {p}%`（灰） | 虚线轨道，无弧 | 中性灰 |
| `AuthExpired` | `登录已失效` | `重新授权后可恢复` | `—` | 虚线轨道，无弧 | 琥珀 |
| `RateLimited` | `限流中` | `{HH:mm} 最后同步`；倒计时另起一行 | 最后已知值（灰）+ `{mm:ss}` 冷却条 | 虚线轨道，**无弧**；冷却条在环外（3pt 高、12 段刻度、宽度=卡宽） | 琥珀 |
| `ServiceDeprecated` | `渠道已停服` | `接口已退役，等待更新` | `—` | 虚线轨道，无弧 | 灰紫 |
| `ParseDegraded` | `数据格式异常` | `{HH:mm} 最后同步` | `最后已知 {p}%`（灰）+ 断点标记（空心点，位于环外同一水平线） | 虚线轨道，**无弧** | 橙 |
| `NeverSynced` | `正在获取数据` | `已等待 {mm:ss}` | `—` | 骨架环（呼吸 1.6s） | 中性灰 |

规则：主文案与副文案分两行渲染，**禁止拼接成一句**（避免“离线 0%”这类误读）。`SYS-1` 菜单栏空间不足时只显示图标变体，不显示状态词（见 §1.5）。

**非 Normal 的额度环永远无弧**（B-03 收敛口径，本节与 §1.2、§1.4 三处一致）：所有时间量（429 冷却、唤醒宽限、重试退避、停服 24h 探测）一律走环**外**的独立组件——
`冷却条`（6pt 下方，3pt 高，12 段刻度，左满右空）或纯文本倒计时。额度环只表达“剩余”，读不到时就只剩虚线轨道。

**第三行固定为时间戳**（M-12）：`OfflineStale / AuthExpired / RateLimited / ParseDegraded / ServiceDeprecated` 的卡片与详情都必须有 `{HH:mm} 最后同步`，
与冷却倒计时分行显示——两个时钟不得共用一个位置。

**暂停不是第八个状态**（M-02）：`paused` 不进入 `AccountHealthState`，而是账号上的正交字段 `pause_until: Option<i64>`（全局暂停另存 `AppSettings.global_pause_until`）。
状态照常按 7 值判定，界面在 `pause_until > now` 时叠加“已暂停”外观；判定与聚合顺序见 §1.5。

### 1.4 圆环编码（剩余，不是已用）

| `remaining` | 弧长 | 颜色 | 中心数字 | 备注 |
| :--- | :--- | :--- | :--- | :--- |
| 100% | 满环 | `#32D74B` | `100%` | 满环 = 健康 |
| 50–99% | 按比例 | `#32D74B` | `{p}%` | 50–60% 为绿→黄过渡带 |
| 20–49% | 按比例 | `#FFD60A` | `{p}%` | |
| 1–19% | 按比例 | `#FF453A` | `{p}%` | **<20% 红色** |
| 0% | 空环（仅轨道） | 轨道 `#FF453A` 20% | `0%` | 仅 Normal+耗尽合法 |
| 非 Normal | **无弧**（虚线轨道 `1.8 / 2.6`） | 灰 `rgba(152,162,179,.42)` | `—` 或最后已知灰值 | 不得用空环冒充 0%；时间量走环外冷却条（§1.3） |

双环：外环主窗口 3.8pt、内环副窗口 3.4pt、间隙 2.6pt；单环渠道描边 4.6pt；端点圆角 + 端点半圆阴影。颜色永远表示"剩余比例"，禁止反向（已用）编码。

### 1.5 菜单栏编码（`SYS-1`）

| 场景 | 图标 | 数字 | 悬停提示 |
| :--- | :--- | :--- | :--- |
| 无账号 | 环轮廓 `○` | 无 | `未添加渠道` |
| ≥1 个 Normal | 环（按最低值着色） | 参与聚合账号的最低剩余 `62%` | `Claude · 工作主力 62%，14:35 重置` |
| 全部非 Normal 但有最后已知值 | 环 + 感叹点 | `—`（不显示数字） | `离线，最后已知 62% · 12:30` |
| 全部 `NeverSynced` | 呼吸骨架环 | 无 | `正在获取数据` |
| 已暂停（`pause_until`） | 灰环 + 斜杠 | 无 | `已暂停刷新，{hh:mm} 恢复` |

聚合集：默认 = 全部账号；被用户隐藏的账号**剔除**（§7.3）。聚合只取 `state == Normal` 的账号；无 Normal 时绝不回落到最后已知值冒充当前值。

**暂停与聚合**（M-02 补全）：

| 场景 | 菜单栏 | 说明 |
| :--- | :--- | :--- |
| 全局暂停（`global_pause_until`） | 灰环 + 斜杠，**无数字**，优先级最高 | 覆盖所有账号，暂停期间不刷新、不评估通知 |
| 部分账号暂停，其余有 Normal | 环 + 数字（只统计未暂停的 Normal） | 被暂停账号从聚合集剔除，与隐藏账号同规则 |
| 全部账号被暂停，无 Normal | 灰环 + 斜杠，无数字 | 不显示最后已知值 |
| 暂停到期 | 下个 tick 立即刷新，不等待 `T_base` | 到期后 5s 内回到常规图标 |

**全局暂停优先于按账号暂停**：两者并存时只按全局计时，恢复时账号各自的 `pause_until` 不叠加。

### 1.6 刷新调度与并发参数

| 参数 | 值 | 说明 |
| :--- | :--- | :--- |
| `T_base` | 300s（默认，可在设置改 60/300/900/1800/3600） | 每账号基础间隔，带 ±10% 抖动 |
| `T_fast` | `max(60, T_base / 2)`；`T_base ≤ 120s` 时 `T_fast = T_base`（不再提速） | 任一窗口 ≤20% 时提速；隐藏账号不提速 |
| 全局并发 | 4 | 跨渠道总在途请求上限 |
| 渠道内并发 | 2 | 同渠道不同账号，避免同 IP 频控 |
| 单账号并发 | 1（single-flight） | 重复请求合并，复用同一 future |
| 连接 / 总超时 | 3s / 8s | 超时计为一次网络失败 |
| 网络失败重试 | 立即 1 次（+250ms 抖动）→ 1s / 3s / 9s | 4 次全失败 → `OfflineStale` |
| `T_wake`（唤醒宽限） | 90s | `didWake` 后 90s 内 G6 不生效：不判 `OfflineStale`、不发通知、卡片呈「恢复中」+ 最后已知 + 时间；90s 后仍无成功刷新才转离线 |
| 429 退避 | `Retry-After` 优先；否则 `min(60 × 2^n, 1800)s` | `n` = 连续 429 次数，成功即清零 |
| 401 处理 | 每次 401 最多触发 1 次 refresh，且两次 refresh 间隔 ≥30s | 刷新成功立即重放 1 次；再 401 → `AuthExpired`。进入 `AuthExpired` 后每 30min 仅做 1 次**只读探测**，不再触发 refresh（杜绝刷新循环） |
| 403 探测 | 退役态下 24h 探测 1 次（±30min 抖动） | 应用更新后立即探测一次 |
| 手动刷新冷却 | 10s | 连点合并为一次 |
| 面板打开软刷新 | 距上次同步 >60s 才发 | 先渲染缓存，再后台更新 |
| 解析失败重试 | 连续 2 次 schema 失败 → `ParseDegraded`，退避 5→10→20→30min | 成功后立即回 `Normal` |
| 唤醒 / 联网 | 全量单次刷新，账号间错峰 500ms | 跳过未到期的 `RateLimited` |

## 4. F2 添加渠道账号（四种鉴权）

### 4.0 渠道 × 鉴权矩阵（首发五项）

| 渠道 | 网页 OAuth | 设备配对码 | 手动粘贴 Token | Cookie 导入 | 首选路径 | 渠道差异要点 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `claude` | 支持（PKCE，推荐） | 不支持 | 支持（备，粘贴会话 Token） | 支持（备，`sessionKey`） | OAuth | 双滑动窗口 5h + 1w |
| `codex` | 支持（ChatGPT OAuth） | 支持（无浏览器环境） | 支持（备） | 不支持 | OAuth | 动态窗口按模型拆分 |
| `workbuddy` | 不支持 | **支持（必选交付，8 位码）** | 支持（企业只读 Key） | 不支持 | 设备码 | 国内/国际站点隔离，积分制 |

### 4.1 概览（四条子流共用）

### 4.7 失败路径（合并表）

| 失败分支 | 判据 | 结果 | 界面与文案 | 恢复与重试 |
| :--- | :--- | :--- | :--- | :--- |
| 用户拒绝授权 | `error=access_denied` | 中止，无凭据残留 | `F2-S4`：「你取消了授权，未保存任何凭据」+「重新授权」 | 手动重试，新会话 |
| 回调超时 | 180s 无回调 | 关 socket、清临时项 | `F2-S4`：「授权超时」 | 「重试」重新生成 PKCE |
| 授权中途关闭浏览器 | 无回调，等待态持续 | 同超时；点「取消」立即终止 | `F2-S2` 等待态 → `F2-S4` | 见 E18 |
| `state` 不匹配 | 常量时间比较失败 | 丢弃该回调，继续等待；累计 2 次即中止 | `F2-S4`：「授权回调校验失败」 | 重新授权 |
| 换 token 5xx | HTTP 5xx | 1s 后重试 1 次 | `F2-S2` 步骤条停留 | 仍失败 → 「授权服务器暂时不可用」 |
| 本地端口全占用 | 53127–53137 均不可绑 | 中止 | `F2-S4`：「本地端口被占用，请关闭代理软件后重试」 | 手动重试 |
| 浏览器不可用 | `open` 失败或被 MDM 禁用 | 中止并给替代路径 | 提示「无法打开浏览器，改用配对码或粘贴 Token」 | 跳 `F2-S5` / `F2-S7` |
| 配对码过期 | 服务端返回 `expired_token` 或倒计时归零 | 停止轮询 | `F2-S6`：「配对码已过期」+「重新生成」 | 见 E19 |
| 配对被拒 | `access_denied` | 停止轮询 | `F2-S6·V2`：「授权被拒绝，可重新生成」 | 手动重试 |
| 轮询 429 | HTTP 429 | `slow_down` +5s，最多 3 次 | 底部「请求过于频繁，稍后继续」 | 仍 429 → 暂停 60s 再续 |
| Token/Cookie 校验失败 | 401 / 缺字段 | 不写凭据 | 就地红字（`F2-S7·V3` / `F2-S8·V3`） | 修正后重试，输入不清空 |
| Keychain 写入失败 | `-25308` / `-34018` | 中止，不落 DB | 「无法写入系统钥匙串」+「重试」 | 解锁钥匙串后重试 |
| 账号数达上限 | 已有 50 个 | 拒绝新增 | 「已达 50 个账号上限，请先删除不用的账号」 | 删除后可加 |
| 网络中断 | `NWPath` unsatisfied | 各子流挂起（码/回调不失效） | 顶部 info banner「网络已断开，恢复后继续」 | 见 E20 |

### 4.8 返回 / 取消

| 操作 | 行为 | 落点 |
| :--- | :--- | :--- |
| `Esc` / 「取消」（会话未取得凭据） | 关 socket、停轮询、删 `aihud-pending/*` | `F2-S1`（渠道上下文保留） |
| 「取消」（已取得 token 未命名） | 先确认「放弃本次添加？已获取的授权将作废」→ 删临时项 | `F2-S1` |
| 返回箭头（会话进行中） | 同取消，需二次确认 | `F2-S1` |
| 关闭面板（未取消） | 会话挂起：OAuth 继续等回调 ≤180s，配对码继续轮询 ≤剩余时间 | 重开面板回到原屏 |

| 取消后再次进入 | 全新 `session_id` / PKCE / 配对码，禁止复用 | `F2-S1` |

### 4.9 幂等性与并发约束

| 操作 | 幂等键 | 约束 |
| :--- | :--- | :--- |
| 添加会话 | `add_session_id`（UUIDv7） | 全局同时仅允许 1 个会话；`F2-S1` 各方式按钮在会话期间置灰 |

| `F5B-N1` | 右键「隐藏」/ 管理列表开关 | 写 `hidden=true`，卡片 200ms 收起并滑入折叠区 | `F5-S4` | 折叠区标题「已隐藏 (3)」 |

### 7.4 删除账号（正常路径与失败路径）

| 节点 | 触发 / 用户动作 | 系统响应 | 屏 ID | 可观察反馈 |
| :--- | :--- | :--- | :--- | :--- |
| `F5C-N1` | 右键/详情「删除」 | 打开确认对话框，列明影响面 | `F5-S3` | 标题「删除「工作主力」？」 |
| `F5C-N2` | 阅读影响面 | 三条：本机凭据（钥匙串）、历史快照、通知设置；并注明「不会影响渠道侧任何数据」 | `F5-S3` | 危险按钮红底白字「删除账号」 |
| `F5C-N3` | 点「删除账号」 | 写 tombstone `deleting=true` | `F5-S3·V2` | 按钮 spinner，禁止重复点击 |
| `F5C-N4` | 中止在途请求 | `abort()` 该账号所有请求，丢弃迟到响应（版本号比对） | — | 卡片变暗 |
| `F5C-N5` | 删 Keychain 项 | 先 `SecItemDelete(aihud/<id>/*)`（失败则标记孤儿并继续），成功后再删本地行（顺序不可反，见 §13.4） | — | — |
| `F5C-N6` | 删本地数据 | 删账号行、快照、通知周期记录、隐藏标记 | — | — |
| `F5C-N7` | 收尾 | 关闭详情（若在详情）、面板重排、toast | `F3-S1` | 「已删除，钥匙串凭据已清除」 |
| `F5C-N8` | 删除的是最后一个账号 | 切到空状态 | `F1-S1` | 菜单栏回环轮廓（无数字） |

| 失败分支 | 判据 | 结果 | 界面与文案 | 恢复与重试 |
| :--- | :--- | :--- | :--- | :--- |
| Keychain 删除失败 | `SecItemDelete != errSecSuccess && != errSecItemNotFound` | 账号从 UI 移除，标记 `orphan_credential=true` | toast「账号已删除，凭据清除将在后台重试」 | 立即/1s/3s 重试 3 次；仍失败 → 设置页「1 条凭据待清理」+ 每次启动重试（E17） |
| DB 删除失败 | SQLite 错误 | 回滚：账号保留，凭据不删 | 「删除失败，请重试」 | 用户重试；不产生半删状态 |
| 删除时正在刷新 | 在途请求存在 | 取消 + 丢弃响应 | 无额外提示 | 版本号已失效，不会复活账号 |
| 重复删除（双击/双实例） | 第二次返回 not-found | 视为成功 | 无提示 | 幂等 |
| 凭据已被他端删除 | `errSecItemNotFound` | 视为成功 | 无提示 | — |

| 幂等 / 并发 | 规则 |
| :--- | :--- |
| 幂等键 | `account_id`；删除是幂等操作，重复执行结果一致 |
| 事务顺序 | tombstone → cancel → Keychain → DB；任一步失败按上表回滚或转孤儿 |
| 多实例 | 单实例锁（`~/Library/Application Support/AIHUD/instance.lock`）；锁失效时以 DB `version` + tombstone 合并，删除优先 |

### 7.5 返回 / 取消

| 操作 | 行为 | 落点 |
| :--- | :--- | :--- |
| 重命名中 `Esc` | 放弃修改，恢复原值，不发请求 | 原屏（`F5-S1` 收起为卡片） |
| 重命名中点击空白 | 等同 `Enter` 保存（Apple 习惯），非法值则保持编辑态 | 原屏 |
| 删除确认 `Esc` / 「取消」 | 关闭对话框，不删除账号、不动凭据 | `F5-S2` 或 `F4-S1` |
| 删除执行中（已写 tombstone） | **不可取消**，显示 spinner 至完成（最长 5s） | — |
| 隐藏后 5s 内点 toast「撤销」 | 反向写 `hidden=false`，卡片回原位 | `F3-S1` |
| 管理列表关闭 | 改动已即时生效，无保存按钮 | `F3-S1` |

### 7.6 幂等性与并发约束（F5 汇总）

| 操作 | 幂等键 | 并发 | 冲突解决 |
| :--- | :--- | :--- | :--- |
| 重命名 | `(account_id, alias_hash)` | 单账号写串行 | 乐观锁 `version`，冲突提示「该账号已在别处更新」 |
| 隐藏 / 取消隐藏 | `(account_id, hidden)` | 覆盖写 | 后写生效；撤销与手动取消隐藏等价 |
| 删除 | `account_id`（tombstone） | 与刷新、另一实例删除互斥 | not-found 视为成功 |
| 删除后重建同名账号 | `(provider, identifier_hash)` | 新 `account_id` | 不复活旧快照与历史 |

## 8. F6 通知与阈值

### 8.1 概览

| 项 | 内容 |
| :--- | :--- |
| 触发条件 | 保存阈值设置；每次刷新回调后的评估；状态迁移为 `AuthExpired`；系统通知权限变化 |
| 前置状态 | ≥1 账号；通知权限状态已知（授权/拒绝/未询问） |
| 屏序列 | `F6-S1`（设置）/ `F6-S2`（横幅 `SYS-2`）/ `F6-S3`（权限被拒引导） |
| 成功出口 | 通知送达并在通知中心留存；点击可深链到详情 |
| 失败出口 | 权限被拒（不发，引导）／发送失败（静默 + 历史记录） |
| 硬规则关联 | 规则 1（仅在 `Normal` 且真实数值下告警，非 Normal 不产生"低额度"告警） |

### 8.2 通知类型与判定

| 类型 | 触发条件 | 文案 | 发送策略 |
| :--- | :--- | :--- | :--- |
| 阈值告警 | `state == Normal` 且任一窗口 `remaining ≤ threshold` | 标题「Claude · 工作主力 5 小时额度剩余 18%」正文「预计 14:35 重置 · 点击查看详情」 | 每 `(account, window, period_key)` 仅 1 次 |
| 合并告警 | 60s 内 ≥2 个账号触发阈值 | 标题「3 个账号额度低于 20%」正文「Claude · 工作主力、Codex · 副号…」 | 合并为 1 条，点击开面板 |
| 登录失效 | `Normal/OfflineStale → AuthExpired` | 标题「Claude · 工作主力 需要重新登录」正文「额度数据已停止更新」 | 每账号 24h 最多 1 次 |
| 恢复通知 | `AuthExpired/RateLimited → Normal` 且此前告警过 | 标题「Claude · 工作主力 已恢复」 | 默认关闭，可在设置开启 |
| 测试通知 | 设置页「发送测试通知」 | 标题「这是一条测试通知」 | 手动，绕过节流，不写周期记录 |
| **不发送** | `RateLimited` / `OfflineStale` / `ParseDegraded` / `ServiceDeprecated` | 仅在面板/详情展示 | 避免噪声；用户主动打开面板即可见 |

### 8.3 正常路径

| 节点 | 触发 / 用户动作 | 系统响应 | 屏 ID | 可观察反馈 |
| :--- | :--- | :--- | :--- | :--- |
| `F6-N1` | 打开设置 → 通知 | 渲染阈值滑块（5–50%，步进 1，默认 20%）+ 三个开关（额度不足/登录失效/恢复） | `F6-S1` | 滑块当前值等宽显示 `20%` |
| `F6-N2` | 拖动滑块 | 实时预览文案「低于 20% 时提醒」，不落盘直到松手 | `F6-S1` | 滑块 280ms 跟随，Reduce Motion 直接跳 |
| `F6-N3` | 松手保存 | 立即用现有快照评估一次（不等下个周期） | `F6-S1` | 若已低于阈值，立即出通知 |
| `F6-N4` | 评估命中 | 写周期记录 `(account, window, period_key, notified_at)` → 投递 `SYS-2` | `F6-S2` | 系统横幅 + 通知中心留存 |
| `F6-N5` | 点击横幅 | 开面板并推该账号详情 | `F4-S1` | 对应卡片高亮 1 次 |
| `F6-N6` | 额度回升 | 回升到 `threshold + 5` 以上才清除告警标记（滞后 5pp） | — | 防止 19%↔21% 抖动重复通知 |

### 8.4 失败路径

| 失败分支 | 判据 | 结果 | 界面与文案 | 恢复与重试 |
| :--- | :--- | :--- | :--- | :--- |
| 通知权限被拒 | `authorizationStatus == .denied` | 不发通知，功能降级 | `F6-S3` 常驻条：「通知已关闭，额度不足时不会提醒」+「打开系统设置」 | 深链 `x-apple.systempreferences:com.apple.Notifications-Settings.extension`；回前台重查权限 |
| 权限未询问 | `.notDetermined` | 首个账号首刷成功后请求一次 | 系统弹窗（非自建屏） | 拒绝后走上一行 |
| 投递失败 | `UNError` | 静默，写通知历史 | 无 toast（避免打扰） | 下个周期重新评估 |
| 阈值非法 | 滑块 5–50 之外 | UI 层不可能产生 | — | — |
| 专注模式 | 系统抑制 | 通知进通知中心不弹横幅 | 无 | 不绕过系统专注（设计选择） |
| 系统时间跳变导致周期键变化 | `reset_at` 变化 | 可能重复告警一次 | 无 | 以 `notified_at` 距现在 <10min 抑制 |

### 8.5 返回 / 取消 与幂等

| 操作 | 行为 / 约束 |
| :--- | :--- |
| `Esc` 关闭设置 | 未松手的滑块改动丢弃（不保存） |
| 「恢复默认」 | 阈值回 20%，开关回默认（额度不足开、登录失效开、恢复关） |
| 幂等键 | `(account_id, window_label, period_key)`；同周期最多 1 条 |
| 节流 | 全局 60s 合并窗口；登录失效每账号 24h 1 条 |
| 并发 | 评估在刷新回调线程串行执行；同一快照并发评估用互斥量保护，避免双发 |
| 隐藏账号 | 评估运行但不发送（§7.3）；「隐藏也提醒」打开则按常规发送 |

## 10. F8 退出与卸载清理

## 12. 状态机：`AccountHealthState`

### 12.1 状态定义与不变量

| 状态 | 语义 | 进入前提 | 是否允许百分比 |
| :--- | :--- | :--- | :--- |
| `Normal` | 最近一次探针成功且数据在 `stale_ttl` 内 | 有有效快照且解析通过 | 允许（唯一） |
| `NeverSynced` | 账号已创建，从未成功获取过数据 | `last_synced_at == nil` | 不允许 |
| `OfflineStale` | 曾有成功快照，最近连续失败或数据过期 | `last_normal_snapshot != nil` | 不允许（仅「最后已知」灰值） |
| `AuthExpired` | 凭据无效且刷新失败 | 401/403 鉴权语义 + refresh 失败 | 不允许 |
| `RateLimited` | 上游 429，处于退避窗口 | 收到 429 或 `Retry-After` | 不允许（仅最后已知 + 冷却） |
| `ServiceDeprecated` | 接口退役 / 403 停服 | 403 + 退役语义 | 不允许 |
| `ParseDegraded` | 返回体结构不符合预期 | schema 连续 2 次失败或数值越界 | 不允许（仅最后已知） |

| 不变量 | 内容 | 违反时的处理 |
| :--- | :--- | :--- |
| `I1` | `OfflineStale ⟺ last_normal_snapshot != nil`（否则应 `NeverSynced`） | 启动自检修正为 `NeverSynced` |
| `I2` | `NeverSynced ⟺ last_synced_at == nil` | 修正为 `OfflineStale` |
| `I3` | 百分比仅在 `Normal` 渲染 | Render Gate 拒绝，落 `—` |
| `I4` | `RateLimited` 未到期不得发请求 | 调度器硬拦截（断言） |
| `I5` | 每个状态都存在通往 `Normal` 的路径（无死锁） | 见 §12.3 自检 |
| `I6` | 状态迁移只由"探针结果 / 用户动作 / 时间事件"触发，禁止 UI 直接改状态 | 状态写入仅经 `state_machine.apply(event)` |

### 12.3 死锁自检（每个状态都必须能回 `Normal`）

| 状态 | 回 `Normal` 的路径 | 最坏耗时 | 是否需人工 |
| :--- | :--- | :--- | :--- |
| `NeverSynced` | 下个周期首刷成功 | `T_base`（5min） | 否 |
| `OfflineStale` | 网络恢复 / 下个周期成功 | 60s 探测 | 否 |
| `AuthExpired` | 重新授权（`T15`）或 30min 探测（`T16`） | 30min（或人工 1min） | 可能 |
| `RateLimited` | `Retry-After` 到期（≤30min） | ≤30min | 否 |
| `ServiceDeprecated` | 24h 探测 / 应用更新 | ≤24h | 否（需上游恢复） |
| `ParseDegraded` | 解析恢复（≤30min 退避） | ≤30min | 否 |

结论：不存在"无法返回 `Normal`"的状态；`ServiceDeprecated` 的最长恢复时间是 24h，页面文案必须给出"等待应用更新"的预期，避免用户误以为卡死。

## 13. 账号生命周期与凭据（Keychain）

### 13.1 Keychain 布局

| 键（account attribute） | 内容 | 类别 | 可访问性 | iCloud 同步 |
| :--- | :--- | :--- | :--- | :--- |
| `aihud/<account_uuid>/oauth` | access/refresh token + `expires_at` | generic password | `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` | **禁止**（`kSecAttrSynchronizable=false`） |
| `aihud/<account_uuid>/token` | 手动粘贴的 Token | generic password | 同上 | 禁止 |
| `aihud/<account_uuid>/cookie` | Cookie 串 | generic password | 同上 | 禁止 |
| `aihud-pending/<session_id>` | 授权过程中的临时凭据 | generic password | 同上 | 禁止 |
| `aihud/install-marker` | `installation_id` + 首次安装时间 | generic password | 同上 | 禁止 |

### 13.2 凭据生命周期

| 时机 | Keychain | 本地 DB | 内存 | 日志 |
| :--- | :--- | :--- | :--- | :--- |
| 授权中 | 写 `aihud-pending/<sid>` | 无 | PKCE verifier（用完清零） | 只记 `session_id` |
| 授权成功 | 转正 `aihud/<id>/<kind>`，删临时项 | 账号行（不含秘密） | 仅在请求构造时短暂持有 | 只记 `credential_fingerprint` |
| 刷新 token | 原地更新（不新建项） | 更新 `expires_at` | 短暂 | 记 `refreshed_at`，不记新 token |
| 重命名 | 更新 `kSecAttrLabel` | 更新 `user_alias` | — | 记旧/新别名 |
| 隐藏 | 不变 | `hidden=true` | — | 记状态 |
| 删除账号 | 先 `SecItemDelete`，成功再删行 | 删行 + 快照 + 通知周期 | 清空 | 记 `deleted` |
| 删除失败 | 保留（孤儿） | 标记 `orphan_credential=true` | — | 记错误码 |
| 清除全部 | 删 service 下所有项 | 删库/缓存 | — | 记 `wiped_at` |
| 卸载重装 | 残留项被检测 | 新库为空 | — | 记孤儿计数 |

### 13.3 日志与 fixture 纪律（规则 4）

| 约束 | 实现 | 检查 |
| :--- | :--- | :--- |
| 探针日志不含秘密 | 请求头值一律输出 `Bearer <redacted:8>`；错误体截断 256 字符并做正则脱敏 | `A05`：CI 扫描日志与 fixtures，命中 `sk-`、`eyJ`、`sessionKey=`、长度 >40 的 base64url 即失败 |
| fixture 只用假凭据 | 所有 fixture 使用 `REDACTED_TOKEN`、`REDACTED_COOKIE` 占位 | 同上 |
| 诊断导出 | 「复制诊断」只导出状态、错误码、耗时、渠道、版本；不含 token/邮箱全量 | 导出前后都跑脱敏器 |
| 崩溃报告 | 关闭自动上传（默认），手动导出走同一脱敏器 | 审核检查 |

### 13.4 删除与清理的执行顺序（不可颠倒）

| 步骤 | 动作 | 失败处理 |
| :--- | :--- | :--- |
| 1 | 写 tombstone（`deleting=true`） | 写失败 → 中止，提示重试 |
| 2 | abort 该账号在途请求 | 忽略错误 |
| 3 | `SecItemDelete` 全部 `aihud/<id>/*` | 重试 3 次；仍失败 → 标记孤儿，继续第 4 步 |
| 4 | 删账号行 / 快照 / 通知周期 / 隐藏标记 | 失败 → 回滚并保留账号（此时凭据可能已删 → 转 `AuthExpired`，不伪装 `Normal`） |
| 5 | 关闭详情、重排面板、toast | — |

## 14. 幂等性与并发约束汇总

| 操作 | 幂等 | 并发 | 冲突解决 |
| :--- | :--- | :--- | :--- |
| 启动 / 初始化 | `installation_id` | 单实例锁（`instance.lock`）+ 进程名检测 | 第二实例激活首实例并退出 |
| 添加账号（保存） | `(provider, identifier_hash)` | 全局 1 个添加会话 | 返回既有账号，提示覆盖或取消 |
| OAuth 回调 / 配对轮询 | `add_session_id` | 单会话单监听 socket | 先到者写，后者丢弃 |
| 首刷 / 周期刷新 | `(account_id, cycle)` | 每账号 single-flight；全局 4、渠道内 2 | 复用同一 future |
| Token 刷新 | `(account_id, expires_at)` + `refresh_lease` 90s | 跨实例（若锁失效）以 lease 互斥 | lease 持有者写，其余读到新值后重放 |
| 重命名 | `(account_id, alias_hash)` | 单账号串行 | 乐观锁 `version`，冲突提示刷新 |
| 隐藏 / 取消隐藏 | `(account_id, hidden)` | 覆盖写 | 后写生效 |
| 删除账号 | `account_id` | 与刷新、与另一实例删除互斥（tombstone） | not-found 视为成功 |
| 阈值修改 | 全量覆盖 | 串行写 | 后写生效；保存后立即评估 1 次 |
| 通知投递 | `(account, window, period_key)` | 评估串行 | 同周期丢弃重复 |
| 手动刷新 | 10s 冷却键 | 合并 | 冷却中点击不排队 |
| 清除全部凭据 | `wiped_at` | 暂停调度器后执行 | 重复执行成功 |

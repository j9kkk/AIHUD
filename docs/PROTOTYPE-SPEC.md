## 0. 这份文档怎么用

| 读者 | 用法 |
| :--- | :--- |
| 审核（红队） | 先看 §6 自查表与 §7 边界矩阵，再去原型里点对应屏 ID 核对屏下「边界验收」三行 |
| 前端实现 | 每个屏的「交互」「边界验收」即组件契约；几何参数见 §1.2，字号与动效见 §1.3 / §1.4 |
| Rust 内核 | 屏承载的状态即 `AccountHealthState`；边界 ID 与 FLOWS §11 一致，可直接映射到状态机迁移 |

原型共 **39 屏**，分 6 个阶段。所有数值为示意数据，但“读不到”的每一种情况都有画面：空、加载、正常、离线、401、429、停服、解析失败，以及时间跳变、唤醒、网络切换、凭据撤销等衍生边界。

## 1. 视觉与几何规范

### 1.1 macOS regular material

| 层 | 实现 | 说明 |
| :--- | :--- | :--- |
| 底 | `linear-gradient(180deg, rgba(38,44,58,.76), rgba(20,24,34,.84))` | 模拟 vibrancy 的上下明暗差 |
| 模糊 | `backdrop-filter: blur(30pt) saturate(180%)` | regular material；有背景色块时可见 |
| 外框 | `.5pt solid rgba(255,255,255,.16)` | 0.5pt 发丝边 |
| 内发光 | `inset 0 .5pt 0 rgba(255,255,255,.20)` + `::after` 的 `.5pt` 内环 | 顶部一道高光，底部一道暗边 |
| 投影 | `0 26pt 56pt rgba(0,0,0,.62)` | 面板浮于桌面之上 |

### 1.2 同心双环几何（Apple Watch 级）

几何不是“看起来像”，而是按点数写死的（SVG `viewBox` 与 pt 1:1）：

| 参数 | 值 | 实现位置 |
| :--- | :--- | :--- |
| 外环（5h）描边 | **3.8pt** | `ring()` 中 `w2` |
| 内环（1w）描边 | **3.4pt** | `w1` |
| 双环间隙 | **2.6pt** | `r1 = r2 - w2/2 - 2.6 - w1/2` |
| 单环渠道描边 | **4.6pt** | `kind='single' / 'credits'` |
| 卡片环直径 / 详情环直径 | 52pt / 74pt | `ring(size=…)` |
| 端点 | `stroke-linecap:round` + 端点半圆（径向渐变 `#FFF → 色 → 暗色`）+ `feDropShadow` | 立体感来自半圆的受光面与外投影 |
| 有色暗底轨 | 先画 `w+1.1pt` 的黑色凹槽，再画 `rgba(color,.17)` 的同径轨道 | 轨道是“刻进去”的，不是贴上去的 |
| 环境光晕 | 同弧加倍线宽 + `feGaussianBlur(stdDeviation=w*0.62)` + 30% 不透明度 | 环在深色材质上有发光溢出 |
| 进度 | `stroke-dasharray = 2πr × pct/100, 2πr`，`rotate(-90)` 从 12 点起 | 比例与 `remaining` 严格正比（A08） |

> 颜色函数：`p ≥ 50 → #32D74B`，`20 ≤ p < 50 → #FFD60A`，`0 < p < 20 → #FF453A`，`p = 0 → 空环（仅轨道）`。非 Normal 一律虚线轨道、无弧。

### 1.3 排版硬约束的实现

| 约束 | 实现 | 自检 |
| :--- | :--- | :--- |
| 百分比绝不换行 | `.pct{white-space:nowrap;display:inline-block}`，卡片内 `.card-nums{min-width:0}` | 静态扫描 + 浏览器 `scrollWidth <= clientWidth` |
| 辅助字号 ≥ 9.5pt | CSS 变量 `--fs-nano:9.5pt`，全站最小字号即它；无 8pt/8.5pt 遗留 | `grep font-size` 全部 ≥9.5pt |
| 数字等宽 | `.pct{font-variant-numeric:tabular-nums}`，所有时间/计数同样 tabular | 计算样式抽查 |
| 2 列 × 2 行 | `.card-page{grid-template-columns:1fr 1fr;grid-auto-rows:98pt}`，每页固定 4 卡 | 屏数固定 per page = 4 |
| 超出翻页 | 渠道内 `.dots` + `←/→` + 横滑；页码按渠道独立记忆 | F3-S2 两页实拍 |

### 1.4 动效

| 场景 | 时长 / 曲线 | Reduce Motion |
| :--- | :--- | :--- |
| 面板入场、详情推入、卡片归位 | 280ms `cubic-bezier(0.16,1,0.3,1)` | 120ms 淡入，无位移 |
| 数字变化 / 环弧过渡 | 280ms；值未变不动画 | 直接替换 |
| 骨架环呼吸 / 等待点 | 1.6s ease-in-out | 静态 60% 不透明度 |

`@media (prefers-reduced-motion: reduce)` 与 `body.reduced` 两处同时实现，后者便于在浏览器里手动演示（F7-S1）。

## 3. 逐屏规格

### 3.1 阶段 01 · 首次进入

> 空账号 · 引导 · 隐私与权限 · 渠道选择

#### `F1-S1` 空状态欢迎（首次启动）

**承载状态**：空账号、无快照、菜单栏仅图标　**覆盖边界**：E01

- **设计意图**：首次启动不做“空白面板”，而是给出单一主行动。整个 DOM 中不存在百分比容器：数值位不是被填成 0%，而是根本没有被渲染。
- **交互**：「添加第一个渠道」→ F1-S3（一次性隐私说明）→ F1-S2；「了解隐私」直接进 F1-S3。Esc 仅收起面板，不重置引导标记。
- **边界验收**：
  - E01 空账号：无 .pct 节点、无空环、无 “0%”；菜单栏为环轮廓且不带数字
  - 引导状态以 has_account 派生，不单独存布尔；重复启动不重复自动展开

#### `F1-S1·V2` 残留凭据横幅（重装后）

**承载状态**：空账号、孤儿凭据　**覆盖边界**：E17

- **设计意图**：重装后空库 + 钥匙串有旧条目是最容易被“静默接管”的路径。这里把残留显式暴露成横幅，只列条目名与类型，绝不显示任何值。
- **交互**：「查看并清除」→ EX-S13 清单；「全部清除」需二次确认；每次启动最多提示 1 次。
- **边界验收**：
  - E17 残留：不自动使用、不渲染任何数值；接管需首刷成功后才出现卡片
  - 条目名只显示 account_id 前后缀，不含秘密；值与 kSecAttrDescription 均不展示

#### `F1-S3` 隐私与权限说明（含权限被拒降级）

**承载状态**：首启、通知/登录项被拒　**覆盖边界**：E29

- **设计意图**：把“为什么需要登录”讲在授权之前，用三条边界替代冗长的隐私政策；右侧是同一屏的降级变体：权限被拒绝不阻断主流程，只降级提醒能力。
- **交互**：可跳过；Esc 返回欢迎页（导航栈深度 ≤2，禁止 S1↔S3 循环）；「打开系统设置」深链到通知面板。
- **边界验收**：
  - E29 权限被拒：核心功能不受影响，仅提醒降级；不出现阻断式弹窗
  - 通知权限申请延后到首个账号首刷成功，避免首屏阻断

#### `F1-S2` 渠道选择器（5 卡）

**承载状态**：空账号、离线可配、渠道禁用　**覆盖边界**：（无，衔接性屏）

- **设计意图**：五个渠道纵向单列，差异只写在“数据格式 / 展示形态”一行里，不引入渠道专属流程。WorkBuddy 带必选徽标，因为它是首发交付项。
- **交互**：hover 抬升 1pt（280ms）；点击进入 F2-S1 并携带 provider 上下文，面板不关闭、宽度不变；禁用卡不可点，只给灰字原因。
- **边界验收**：
  - 渠道被版本禁用：该卡置灰并给原因，不隐藏（隐藏会让用户以为渠道消失）
  - 首启离线：允许配置，凭据先落钥匙串；首刷失败一律 NeverSynced
  - 五渠道差异只在数据格式与展示形态，不新增专属状态或文案分支

### 3.2 阶段 02 · 账号配置

> 四条鉴权子流：OAuth / 配对码 / Token / Cookie

#### `F2-S1` 鉴权方式选择（含账号上限）

**承载状态**：正常、上限拒绝　**覆盖边界**：E31

- **设计意图**：四种鉴权放在同一层级，按“推荐 / 可用 / 不适用”排序，不给渠道专属入口。右侧是同屏的上限变体：按钮置灰而不是隐藏，用户仍能看懂为什么不能加。
- **交互**：选中即进入对应子流（A→F2-S2 / B→F2-S5 / C→F2-S7 / D→F2-S8）；会话进行中其余方式按钮置灰；300ms 内重复点击只导航一次。
- **边界验收**：
  - E31 账号上限 50：拒绝新增但保留编辑/删除入口，不出现新的失败弹窗
  - 不支持的鉴权方式置灰且写明“不适用”，避免用户走进死路再报错

#### `F2-S2` 网页 OAuth 等待回调

**承载状态**：等待回调、校验中　**覆盖边界**：（无，衔接性屏）

- **设计意图**：等待态用呼吸点表达“在等外部动作”，绝不用百分比进度（进度不可知，百分比会变成谎话）。右侧展示拿到 code 之后的校验瞬间。
- **交互**：「重新打开浏览器」复用同一 state；「取消」立即关 socket 并删临时项；45s 追加重开提示但不改状态；关面板不影响会话（≤180s）。
- **边界验收**：
  - 等待与校验期间无任何额度数值位（账号尚未创建）
  - state 不匹配：累计 2 次才中止，避免一个过期标签页把整次授权作废
  - 添加会话内不预刷新 token（规则 5），回调换到的 token 直接使用

#### `F2-S4` OAuth 失败与中断

**承载状态**：access_denied、超时、端口占用　**覆盖边界**：E18

- **设计意图**：失败页只回答三件事：发生了什么、有没有留下东西、下一步点哪里。三张卡对应三条不同的失败判据，文案不复用同一句“授权失败”。
- **交互**：「重新授权」新建 session_id 与 PKCE；「改用其他方式」回 F2-S1；Esc 同取消，不二次确认（此时无凭据）。
- **边界验收**：
  - E18 中途关闭浏览器：等待态保持至 180s 再中止，清 socket 与 aihud-pending 项
  - 浏览器不可用/被 MDM 禁用：直接提示改用配对码或 Token，不重试打开
  - 任何失败分支都不产生账号行、不在界面上出现 0%

#### `F2-S5` 设备配对码（含过期变体）

**承载状态**：等待配对、倒计时、过期/被拒　**覆盖边界**：E19

- **设计意图**：配对码是 WorkBuddy 的首选路径：8 位码用等宽字体 + 0.12em 字距，最后 60 秒转琥珀。进度条是不确定态的细条，只表示“还在等”，不表示完成度。
- **交互**：站点切换即作废旧码；点击码复制；过期后整块灰化加删除线，只保留「重新生成」；重新生成后 2s 起轮询。
- **边界验收**：
  - E19 过期/被拒：停止轮询、不写凭据、旧码灰化删除线，无数值区
  - 站点（国内/国际）为凭据隔离维度，切换必须先作废旧码
  - 轮询 429 走 slow_down +5s，最多 3 次，仍 429 则暂停 60s

#### `F2-S7` 手动粘贴 Token（校验中 / 格式错 / 401 / 离线保存）

**承载状态**：校验中、格式错、401、网络失败　**覆盖边界**：（无，衔接性屏）

- **设计意图**：密文显示是默认态，「按住显示」是短暂动作；本地先做格式校验再发请求，避免把格式错误变成 401 噪音。任何一次失败都不落盘。
- **交互**：输入即校验（不发请求）；「验证并保存」时输入框禁用 + spinner；401 保留输入；网络失败给二次确认，选「保存」→ NeverSynced。
- **边界验收**：
  - 凭据零明文：输入框只渲染掩码，界面与诊断导出均不含 token 明文
  - Token 校验失败不写钥匙串、不建账号行（规则 4）
  - 网络失败保存后进入 NeverSynced：数值区为「—」，绝不 0%

#### `F2-S8` Cookie 导入（缺字段 / 网关拦截）

**承载状态**：解析中、缺必需项、HTML 拦截　**覆盖边界**：（无，衔接性屏）

- **设计意图**：只列 cookie 名称与到期时间，值永远不渲染——这是“能看见校验结果但不泄露秘密”的唯一形态。右侧是 E11 的前置兄弟：200 但返回 HTML 时当场判网关拦截。
- **交互**：两个 tab（粘贴 / 文件）；缺必需项即时中止不发请求；「验证并保存」后整段写钥匙串；HTML 响应给出诊断入口。
- **边界验收**：
  - 凭据零明文：cookie 值从不渲染，列表只有名称与到期时间
  - 缺必需项不发请求（避免用不完整登录态打上游）
  - 200 但 HTML → 网关拦截，不写凭据（EX-S11）
  - Cookie 等同登录态，渠道改密后失效 → 走 AuthExpired 而非离线

#### `F2-S9` 重复账号检测与命名保存

**承载状态**：已存在、重名校验、保存　**覆盖边界**：E15

- **设计意图**：重复添加不报错、不静默新建，而是给出“覆盖 / 取消”的二选一。命名页只做一件事，同时把将要写入的位置（钥匙串项）显式写出，让用户看到边界。
- **交互**：覆盖为原子操作；别名实时校验 1–24 字符，重名仅灰字提示不阻断；Esc 放弃编辑。
- **边界验收**：
  - E15 重复授权：幂等键命中即返回既有账号，覆盖时先清快照再首刷（防新旧混显）
  - 重名允许保存但提示，避免把命名规则变成阻断
  - 保存按钮 disabled + spinner，重复提交返回同一账号

#### `F2-S10` 首次同步中 / 首刷失败

**承载状态**：NeverSynced、首刷失败　**覆盖边界**：（无，衔接性屏）

- **设计意图**：NeverSynced 与 OfflineStale 必须长得不一样：前者没有“最后已知值”可退，所以数值区只能是「—」和骨架环，而不是灰数字。右侧是同一状态的失败分支。
- **交互**：首刷成功 → 卡片 280ms 入场并落 F3-S1；失败保留诊断码与重试按钮；可关闭面板，后台继续。
- **边界验收**：
  - NeverSynced 数值区为「—」，不使用 0% / 空环代替
  - T01→T02 只有解析通过才进 Normal；失败保留 NeverSynced 并记录诊断码
  - 首刷不受 T_base 限制（保存即刷），失败后回归常规退避

### 3.3 阶段 03 · 一级巡检

> 菜单栏 → 面板 → 渠道内翻页 → 局部刷新

#### `F3-S1` 面板基础（单账号 / 多渠道混排）

**承载状态**：Normal、耗尽、积分池　**覆盖边界**：E02

- **设计意图**：面板 360pt，每渠道一个 section，卡片 2 列 × 最多 2 行。单账号时右列留空而不是把卡片拉宽——拉伸会让 15pt 数字失去与环的比例关系。右侧面板第 2 张卡是唯一合法的 0%：Normal + 已耗尽。
- **交互**：点卡片进 F4；右键出上下文菜单（重命名/隐藏/立即刷新/复制诊断/删除）；Esc 收起，焦点回上一个应用。
- **边界验收**：
  - E02 单账号：单 section 无页码点，卡片占 1 列、右列留空
  - 卡片间距 10pt / 圆角 12pt / 环 52pt，低额度（<20%）数字与环同时转红
  - 0% 的唯一合法来源：state=Normal 且 remaining=0，文案追加「已耗尽 · 14:35 重置」，环为空环（仅轨道）
  - 百分比 white-space:nowrap + tabular-nums，窄卡片下也不换行

#### `F3-S1·V2` 单环渠道（无 5h 窗口）

**承载状态**：Normal、窗口缺失　**覆盖边界**：E04

- **设计意图**：gemini 只有一个周配额窗口，因此面板里只有单环：环数由窗口数量驱动，不是渠道品牌驱动。缺失的窗口用一行灰字说明，不占百分比位。
- **交互**：与双环卡片完全一致的交互（点开详情、右键菜单），不因为环数不同产生分支。
- **边界验收**：
  - E04 无 5h 窗口：primary_window=null，不合成数据、不以 100% 冒充「无限制」
  - 单环渠道描边加粗到 4.6pt，保证与双环渠道同视觉重量
  - 环数 = 窗口数量（由 MetricVisualKind 决定），不新增渠道专属分支

#### `F3-S2` 渠道内翻页（2 列 × 2 行）

**承载状态**：Normal 多页　**覆盖边界**：E03

- **设计意图**：每页固定 4 卡，第 5 张起翻页而不是让面板变长或把卡片压小。两只面板分别是第 1、2 页，可直接对比页码点与空位槽。
- **交互**：页码点可点；两指横滑；聚焦时 ←/→；页码按渠道独立记忆（会话内）。左页 4 卡、右页 1 卡 + 3 空位。
- **边界验收**：
  - E03 超出 4 卡：渠道内翻页，不改变卡片尺寸与栅格
  - 末页不足 4 卡时补虚线空位，不拉伸、不补假卡
  - 页码点最多 6 个，超出折叠为 3/7（见 F3-S5）

#### `F3-S3` 局部刷新中（缓存不闪断）

**承载状态**：加载中、部分离线　**覆盖边界**：E28、E07

- **设计意图**：刷新时旧值继续显示，只有顶部一条不确定进度条在动：不用骨架屏盖住已有数据（那会让用户以为数据没了）。失败的账号单独转离线，其他账号照常。
- **交互**：面板打开时距上次同步 >60s 才发请求；手动刷新 10s 冷却，冷却中点击不排队；返回后数字 280ms 滚动，值未变则不动画。
- **边界验收**：
  - E28 连点合并为一次，按钮显示冷却进度而非禁用无反馈
  - E07 超时只影响该账号：卡片角标 + toast，绝不覆盖已显示数值为 0
  - 软刷新期间不出现骨架屏覆盖已有数据（规则 3 的界面侧约束）

#### `F3-S5` 40 账号密度与检索

**承载状态**：高密度、分页折叠　**覆盖边界**：E03

- **设计意图**：40 个账号不改变栅格，只增加页数；页码点超过 6 个折叠成「第 3 / 7 页」。chips 承担检索，首行即显示每渠道计数。
- **交互**：chips 横向可滚，选中态 0.5pt 内发丝边；点「跳转」可输入页码；筛选后页码重置到 1。
- **边界验收**：
  - E03 20+ 账号：每页 4 卡不变、页码折叠为 n/N
  - 首帧 < 50ms 由虚拟化保证；仅 Normal 卡渲染百分比节点
  - chips 计数来自本地快照，不发请求

#### `F3-S4` 菜单栏图标五态（SYS-1）

**承载状态**：空、Normal、全异常、NeverSynced、已暂停　**覆盖边界**：E26

- **设计意图**：菜单栏只有 12pt 见方，必须用形状而不是颜色表达状态。五态并排放在同一屏，方便逐条比对“什么时候允许出现数字”。
- **交互**：悬停出 tooltip（含别名、数值、重置时间）；点击展开面板；⌥ 点击直接刷新（10s 冷却）。
- **边界验收**：
  - E26 聚合只取 Normal：无 Normal 时数字位为「—」，绝不回填最后已知值
  - 已隐藏账号不参与聚合（避免长期拉低菜单栏数字）
  - 空间不足时只显示图标变体，不显示状态词

### 3.4 阶段 04 · 二级详情

> 双环 / 积分 / 单窗口 / 异常横幅

#### `F4-S1` 双环详情（claude）

**承载状态**：Normal　**覆盖边界**：（无，衔接性屏）

- **设计意图**：详情是“已用 / 剩余”最容易被误读的地方：表头显式写「剩余」，环与数字同源于 remaining，另有一行图例说明外环 5h / 内环 1w 的线宽与间隙。
- **交互**：‹ / Esc / 右滑返回，保留原渠道页码与滚动位置；刷新按钮 10s 冷却；删除为红色文字按钮，走 F5-S3 确认。
- **边界验收**：
  - 环编码剩余而非已用：<20% 转红，满环 = 健康
  - 热力图仅 Normal 渲染；缺数据为空格，不画 0 值格子
  - 钥匙串项只显示「存在 / 缺失」，不显示任何秘密
  - 详情与面板共享 single-flight，不产生第二条在途请求

#### `F4-S1·V2` 5h 复位而 1w 未复位

**承载状态**：Normal、窗口级复位　**覆盖边界**：E21

- **设计意图**：复位是窗口级事件：外环回满到 100%，内环保持 61%。两块小卡把“谁变了、谁没变”并排放，防止用户以为额度整体恢复而误用。
- **交互**：复位后 30s 内补刷一次；不播放“整卡恢复”动画，只让外环单独 280ms 过渡。
- **边界验收**：
  - E21 分窗口判定：某窗口重置只影响该窗口，不整卡清零
  - 100% 只在 Normal 且窗口刚重置时出现，来源是真实快照
  - 复位不改变 AccountHealthState，也不重置告警周期之外的其他窗口

#### `F4-S2` 积分详情（workbuddy）

**承载状态**：Normal、积分池　**覆盖边界**：E05

- **设计意图**：积分渠道的主读数用绝对值，不用百分比：`15,240 / 20,000 积分`，单位永远随数字出现。环只是比例的可视化补充，刻度环提醒它不是时间窗口。
- **交互**：积分池无重置行；即将过期单独一行；「过期包不计入分母」在行内直接说明（对应开放问题 Q5）。
- **边界验收**：
  - E05 积分制：reset_at=null，无重置时间行；不伪造 5h 周期
  - total 缺失时降级为绝对值 + 「总量未知」，不出百分比（G3）
  - 过期包不计入 total 分母；如需计入须先改产品规则并回写文档

#### `F4-S3` 单窗口详情（gemini）

**承载状态**：Normal、窗口缺失　**覆盖边界**：E04

- **设计意图**：详情页的环数、表格行数、热力图都随窗口数量变化；缺失的 5h 只有一行灰字，没有环、没有 0%、没有 100%。
- **交互**：与双环详情完全相同的返回、刷新、操作区；不因为渠道不同出现新的按钮。
- **边界验收**：
  - E04 无 5h 窗口：只渲染 1 行表格 + 1 个环，不以 100% 表示「无限制」
  - 「无限制」与「无此窗口」文案分离，避免语义混用
  - 窗口缺失不改变 Render Gate 的其它判定（G1/G3/G4/G5/G6 照常）

#### `F4-S4` 详情页异常横幅（离线 / 401 / 停服）

**承载状态**：OfflineStale、AuthExpired、ServiceDeprecated　**覆盖边界**：E06、E08、E09

- **设计意图**：详情横幅要说清“这是旧数据 / 这是凭据问题 / 这是上游退役”，三者的恢复路径完全不同。共同的视觉规则：环变虚线、数值灰化或 —，绝不出现彩色百分比。
- **交互**：离线可重试；401 高亮「重新授权」并跳到对应鉴权子流；停服给「检查更新」，不提供无效的重试按钮。
- **边界验收**：
  - E06 离线：最后已知 + 灰化 + 不画弧，不用空环冒充 0%
  - E08 401：数值区「—」，不当当前值沿用过期数字；30min 只读探测，不刷新循环
  - E09 停服：不伪造数值，窗口表标日期；24h 探测 + 应用更新触发
  - 三种异常都只影响单账号，其他账号照常刷新（规则 3）

### 3.5 阶段 05 · 异常与边界

> 离线 / 401 / 429 / 停服 / 解析降级 / 时间 / 唤醒 / 撤销

#### `EX-S1` 离线（OfflineStale）

**承载状态**：OfflineStale、部分离线　**覆盖边界**：E06、E07

- **设计意图**：离线卡的三行是固定的：状态文案、最后已知值（带前缀 + 灰化）、最后同步时间。环退化为虚线轨道——虚线表示“不知道”，空环会读成 0%。
- **交互**：「重试」立即发起一次（10s 冷却）；其他账号照常按自己的周期刷新；面板级只出一条合并 toast，不逐卡弹窗。
- **边界验收**：
  - E06 离线：三行灰字 + 虚线轨道 + 不画弧；不用空环冒充 0%
  - E07 超时：只影响该账号，last_synced_at 不动，不写入任何 0 值
  - 规则 3：单渠道故障独立熔断，其余渠道继续刷新（右卡仍为绿色正常态）

#### `EX-S1·V3` 全渠道同时失败（E30）

**承载状态**：全异常、菜单栏无数字　**覆盖边界**：E30

- **设计意图**：最坏情况下界面依然是“可读的”：每个账号给出自己的异常类型，整体给一条横幅。菜单栏退化成灰环 + —，不回落最后已知值来假装正常。
- **交互**：各账号按各自退避重试，全局 60s 兜底探测；任一账号恢复只回自己那张卡，不做整体重载。
- **边界验收**：
  - E30 全失败：全部状态化、零百分比，不允许平均成一个数
  - 菜单栏无 Normal → 数字位「—」，不回填最后已知（E26 联动）
  - 每个账号的退避相互独立，全局只加 60s 兜底探测

#### `EX-S2` 登录失效与钥匙串锁定

**承载状态**：AuthExpired、已暂停　**覆盖边界**：E08、E25

- **设计意图**：401 与“钥匙串打不开”必须分开：前者要用户重新授权，后者要用户解锁。两者都不能把数据写成 0，也不能拿旧数字继续显示成当前值。
- **交互**：「重新授权」进入 F2 对应子流，成功后 T15 → NeverSynced → Normal；钥匙串重试成功即恢复；两次 refresh 间隔 ≥30s。
- **边界验收**：
  - E08 401：数值区「—」，停轮询，30min 只读探测，禁止刷新循环
  - E25 钥匙串锁定：暂停刷新而非判定失效，不解锁就一直保持「—」
  - 同屏另一账号仍为 Normal（规则 3 的可视证据）

#### `EX-S3` 限流冷却（RateLimited）

**承载状态**：RateLimited、冷却倒计时　**覆盖边界**：E10

- **设计意图**：429 最容易犯的错是把冷却进度画成额度环。这里用两套视觉：冷却弧带 12 段刻度、琥珀色、中心是倒计时；额度环退成虚线轨道。
- **交互**：倒计时以 Retry-After 为准；到期自动探测，成功 T18 回 Normal；期间该账号请求数为 0，其他账号不受影响。
- **边界验收**：
  - E10 429：冷却弧只表示时间；额度区只给最后已知灰值
  - 未到期不得发请求（I4 硬拦截）
  - 无 Retry-After 时走 min(60×2^n,1800)s 退避，界面显示同一倒计时

#### `EX-S4` 渠道停服（ServiceDeprecated）

**承载状态**：ServiceDeprecated　**覆盖边界**：E09

- **设计意图**：停服用灰紫而不是红色：它不是用户的错误，也不是紧急故障，而是“等更新”。文案给出预期（24h 探测 / 应用更新），避免用户以为卡死。
- **交互**：停止常规轮询；「检查更新」打开应用更新面板；应用更新后立即探测一次。
- **边界验收**：
  - E09 403 退役：立即停常规轮询，不影响其他渠道
  - 不伪造数值：详情窗口表只读并标日期
  - 网络失败时状态不变，仅副文案切换（T22）；401 优先判凭据（T23）

#### `EX-S5` 解析降级与越界值

**承载状态**：ParseDegraded、越界数值　**覆盖边界**：E11、E32

- **设计意图**：解析失败不等于离线：网络是通的，说“离线”会把用户引向错误的排查方向。橙色断点弧既保留了上次的形态，又明确表示它已不可信。
- **交互**：退避 5/10/20/30min；成功后立即回 Normal（断点弧 280ms 变实心弧）；「复制诊断」只导出字段名与错误码。
- **边界验收**：
  - E11 连续 2 次 schema 失败才降级，保存最后快照并记录缺失字段名
  - E32 越界值：判 ParseDegraded，原值只进诊断日志，绝不 clamp 成 0%/100%
  - 解析失败绝不返回 0；详情可查「缺失字段」与原始值

#### `EX-S6` 时间跳变 · 时区 · 负倒计时

**承载状态**：CLOCK_SKEW、DST、重置未刷新　**覆盖边界**：E12、E13、E22

- **设计意图**：时间类异常的共同风险是“用时间反推额度”。三块画面分别锁定：跳变时倒计时显示 —、时区变化只改标签、倒计时为负时显示「已重置，等待刷新」而不是 100%。
- **交互**：跳变后立即全量刷新 1 次；时区变化下个 tick 重算标签；负倒计时触发 1 次补刷（10s 去重）。
- **边界验收**：
  - E12 时钟跳变：stale 判定改用单调时钟，倒计时替换为 —
  - E13 跨时区/DST：UTC 存储，只重算标签，不清空窗口
  - E22 倒计时为负：不渲染负数，不当作 100%，标「已重置，等待刷新」

#### `EX-S7` 睡眠唤醒与网络切换

**承载状态**：唤醒恢复、路径变化　**覆盖边界**：E14、E20

- **设计意图**：唤醒与换网都是“环境变了”，界面的第一反应应该是“我在恢复”，而不是把旧数据当成新数据。两条横幅语气一致，1.5s / 10s 两个时限写清楚。
- **交互**：唤醒 1s 内叠「正在恢复连接…」，超 10s 转离线文案；换网取消在途请求，stale 账号立即刷新。
- **边界验收**：
  - E14 唤醒：取消退避、错峰全量刷新（500ms），旧值标 stale 不显示 0
  - E20 网络切换：取消在途请求，跳过未到期 429，1.5s 后横幅消失
  - 两条路径都不重置任何窗口，也不清空快照

#### `EX-S12` 凭据被其他端撤销

**承载状态**：AuthExpired、invalid_grant　**覆盖边界**：E16

- **设计意图**：改密 / 登出全部设备是最常见的 401 来源，用户往往不知道发生了什么。通知里说“在别的设备被撤销”，比“401”有用得多。
- **交互**：点击通知 → 打开面板 → 推 F4-S4 → 「重新授权」；同一账号 24h 内只通知 1 次。
- **边界验收**：
  - E16 凭据被撤销：401 + invalid_grant → AuthExpired，停止自动刷新
  - 每账号 24h 最多 1 次「需要重新登录」通知，避免通知风暴
  - 禁止刷新循环：只做 30min 只读探测

### 3.6 阶段 06 · 设置与管理

> 重命名 / 隐藏 / 删除 / 通知 / 偏好 / 退出

#### `F5-S2` 管理列表（排序 / 隐藏）

**承载状态**：管理态、已隐藏　**覆盖边界**：（无，衔接性屏）

- **设计意图**：管理页把“显示/隐藏”和“删除”分开：开关只影响展示位，删除才动凭据。行内只显示状态词，不给百分比，避免管理页被当成巡检页。
- **交互**：拖动排序；开关即时写库；「完成」返回面板；无保存按钮（改动即时生效）。
- **边界验收**：
  - 隐藏不改变 AccountHealthState，仅移出分组与聚合（E23）
  - 隐藏账号仍计入 50 上限
  - 行内不显示百分比，避免在管理语境下被读成实时额度

#### `F5-S1` 别名原地重命名（非法输入）

**承载状态**：编辑中、超长、空名　**覆盖边界**：（无，衔接性屏）

- **设计意图**：重命名在卡片原地完成，不弹对话框：用户改的就是最终看到的那一行。错误就地红字 + 计数，不产生 toast 噪音。
- **交互**：双击别名进入编辑并全选；Esc 放弃；点击空白等同保存；持久化失败回滚并 toast「重命名未保存」。
- **边界验收**：
  - 空名/纯空白拒绝提交；超长阻止输入并提示 24 字符上限
  - 重名允许保存，仅灰字提示（不阻断，避免命名规则变成阻碍）
  - 并发改名以版本号冲突失败，提示「该账号已在别处更新」

#### `F5-S3` 删除确认 / 删除中 / 凭据清理失败

**承载状态**：确认、删除中、孤儿凭据　**覆盖边界**：E24

- **设计意图**：删除确认列出三类影响面，并明确“不影响渠道侧”。执行中不可取消、只有 spinner；钥匙串删失败时如实显示孤儿标记，而不是假装干净。
- **交互**：确认后进执行态；失败不产生半删状态，设置页常驻「1 条凭据待清理」；重复删除按 not-found 视为成功。
- **边界验收**：
  - E24 在途刷新：先 abort 再删，迟到响应按版本号丢弃，不产生复活账号
  - 删除顺序 tombstone → abort → Keychain → DB，不可颠倒（§13.4）
  - Keychain 删除失败 → 账号消失但标记孤儿，必须可见（A19）

#### `F5-S4` 隐藏收纳（折叠区）

**承载状态**：已隐藏、全部隐藏　**覆盖边界**：E23

- **设计意图**：隐藏是收纳不是停用：折叠区里的行只说“还在刷新”，不显示百分比——折叠行没有环，也没有数字位，从根上避免被读成实时额度。
- **交互**：隐藏后 5s 内可点 toast「撤销」；展开折叠区行高 32pt；「取消隐藏」回原排序位（280ms 归位）。
- **边界验收**：
  - E23 隐藏：仍按 T_base 刷新，不参与聚合/通知/提速；折叠行不显示百分比
  - 隐藏最后一个可见账号 → 空态但保留管理入口，菜单栏无数字
  - 隐藏不改 AccountHealthState（T28）

#### `F6-S1` 阈值设置与系统通知（SYS-2）

**承载状态**：阈值告警、合并通知、权限被拒　**覆盖边界**：E27

- **设计意图**：阈值用分段 + 滑杆双呈现，并说明“同周期只提醒一次”。右侧是系统通知的三种形态：单条、合并、以及权限被拒时的常驻提示。
- **交互**：保存后立即评估；60s 内多次命中合并；点击通知开面板并推详情（F4）。
- **边界验收**：
  - E27 通知风暴：60s 合并为 1 条，列出前两个别名
  - 同 period_key 不重复提醒，滞后 5pp 才复位（防抖）
  - E29 权限被拒：设置页常驻提示 + 深链，不阻断核心功能

#### `F7-S1` 通用偏好与减弱动态

**承载状态**：设置、Reduce Motion　**覆盖边界**：（无，衔接性屏）

- **设计意图**：偏好页把“影响刷新节奏”和“影响观感”的两类设置分开。减弱动态不是简单关掉所有动画，而是把 280ms 位移换成 120ms 淡入。
- **交互**：所有开关即时生效；刷新频率切换后按新 T_base 重排；快捷键冲突在 F7-S2 处理。
- **边界验收**：
  - Reduce Motion：无位移动画、过渡 ≤120ms，环弧长语义不变
  - 刷新频率下限 60s；T_fast 只在 ≤20% 时启用
  - 菜单栏数字可关，但状态图标始终存在

#### `F8-S1` 退出确认与清除全部凭据

**承载状态**：退出、暂停、清空　**覆盖边界**：（无，衔接性屏）

- **设计意图**：退出与暂停分开：多数人想要的是“别再刷了”，不是“关掉应用”。清除凭据是唯一需要输入文字的二次确认，因为它同时动钥匙串与本地库。
- **交互**：暂停 30 分钟后到点自动恢复；退出不删凭据；清除先暂停调度器再执行，重复执行成功。
- **边界验收**：
  - 退出/暂停都不触碰钥匙串（规则 4 的边界）
  - 清除全部：先暂停调度，再删 service 下所有项，记录 wiped_at
  - 清除后回到空状态 F1-S1，不残留任何数值位

## 7. 状态矩阵（7 状态 × 视觉编码）

> 规则：**只有 Normal 允许出现百分比主读数**；其余状态一律「状态文案 + 最后已知值（灰化、不进环）+ 时间戳」。

| 状态 | 额度环 | 圆心/主数值槽 | 辅助行 | 菜单栏 | 是否自动恢复 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `Normal` | 实弧，填色=剩余；<20% 红 | `62%` 等宽数字 | `外 5h 62% 恢 1h04m` | 圆环 + 最小剩余百分比 | — |
| `OfflineStale` | 虚线轨，无弧 | `最后已知` / 灰值 `62%` | `{HH:mm} 最后同步` | 虚线环轮廓，无数字 | 网络恢复后自动 |
| `AuthExpired` | 虚线轨 + `!` 形状标记 | 无百分比 | `重新授权后可恢复` | `!` 字形 | 重新授权后 |
| `RateLimited` | 虚线轨，无弧 | `最后已知` / 灰值 | 独立 **12 段冷却条** + `{mm:ss} 后重试` + `{HH:mm} 最后同步` | `Ⅱ` 字形 | `Retry-After` 到期自动 |
| `ServiceDeprecated` | 斜杠划断的环 | 无百分比 | `接口已停服` + 迁移提示 | 斜杠环 | 需升级/迁移，不自动 |
| `ParseDegraded` | 虚线轨 + 断点弧 | `最后已知` / 灰值 | `{HH:mm} 最后同步` + 诊断码 | 断点环 | 解析成功即恢复 |
| `NeverSynced` | 骨架环（呼吸） | `—` | `已等待 {mm:ss}` | 环轮廓，无数字 | 首刷成功后 |

`paused`（用户暂停）为**正交标志**而非第八态：暂停期间保留最后读数与状态，菜单栏按「全局暂停优先、其次按账号暂停」聚合。

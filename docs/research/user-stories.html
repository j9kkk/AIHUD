00怎么读这份规格

三条原则，决定这份文档和"功能清单"的区别。

状态优先
不是页面，是状态

每个渠道卡片有 8 种状态。规格不按页面组织，按"状态 × 平台"组织，因此不存在"这个状态没人管"的空白。

边界即需求
50 条显式列出

离线、401、429、返回 HTML、时区跳变、托盘折叠……每条都写死期望行为，测试可直接抄成用例。

不撒谎
数据可信度是功能

过期必须标注、失败不得显示 0%、停服要说明原因并给迁移路径。这是本产品最容易被做成"看起来能用"的地方。

可机器核对
覆盖率不是形容词

第 04 节的矩阵由脚本从故事数据生成：8×4=32 个格全部非空，可见性 3×4=12 个格全部非空。

01渠道卡片的八种状态

所有渠道统一收敛到这 8 个状态。UI、通知、数据保留策略都按状态定义，而不是按渠道写分支。

未配置 授权中 正常 过期(stale) 需重登 限流 已停服 不支持
从触发到UI 必须发生什么谁触发
未配置添加渠道授权中打开授权流程，展示正在进行用户
授权中拿到快照正常徽标出现第一个数字系统
授权中失败/取消未配置回到空状态并保留错误摘要系统/用户
正常连续 3 次失败（网络）过期(stale)保留旧值 + 时间戳 + 灰点系统
过期(stale)下一次成功正常静默恢复，不弹通知系统
正常/过期401 / 403 鉴权失败需重登卡片变"需重登"，旧百分比隐藏系统
需重登用户重新登录授权中复用原卡片位置，不新增卡片用户
正常429 + Retry-After限流显示可重试时间，按钮禁用系统
限流退避到期且成功正常恢复显示，不提示"已恢复"系统
正常/过期上游停服信号已停服说明 + 迁移路径（Gemini→Antigravity）系统
正常账号类型不支持不支持说明 + 可操作建议，不再重试系统
任意用户暂停暂停零请求零通知，图标加暂停标记用户
暂停到期/手动恢复未配置*立即刷新一轮，失败则按错误态处理系统/用户
硬规则：只有「正常」状态允许显示百分比。其余状态一律显示状态文案 + 最后一次已知值（带时间戳），任何情况下都不允许把"读不到"渲染成 0% 或 100%。

07WorkBuddy 接入：从"抓包猜"升级为"已实测"

你指的反代项目确实把这条路走通了。我读了它的源码并直接打了一遍官方接口，结论比上一版报告乐观得多。

能力接口实测 / 证据
发起授权POST https://www.workbuddy.cn/v2/plugin/auth/state?platform=workbuddy-web本机实测 200，返回 data.state（UUID）+ data.authUrl（官方登录页）
换取 token{api}/v2/plugin/auth/token?state=… + …/login/account?state=…源码 crates/…/modules/oauth.rs，轮询式，等价于设备码流程
积分余额POST https://www.workbuddy.cn/billing/meter/get-user-resource-summary无凭据访问实测 401（端点存在，网关 APISIX）；需 Authorization: Bearer + X-User-Id / X-Enterprise-Id / X-Domain
用量明细POST /billing/meter/get-user-request-usage（国内 workbuddy.cn / 国际 workbuddy.ai）源码 official_usage.rs；按账号 domain 选域名，混用会拿到 401 HTML
字段资源包 total / used / expireAt / expired；汇总 totalCapacity / totalRemaining源码 credits.rs；商品码 p_tcaca，另有 paid/free packages 两个明细接口
结论修正：WorkBuddy 不需要"抓包 + cookie"这种最脏的做法，它有可用的设备登录流程（打开官方页面 → 轮询换 token），和 Claude/Codex 的体验一致。因此它可以进 P0，而不是 P2。剩余风险只有两条：端点未公开（随时可改）、国内版与国际版是两套账号体系且端点不同（US-07 的边界条件已覆盖）。
仍属于灰色地带：这些接口是客户端自用的，没有公开文档与 SLA；只读展示自己的积分不代跑推理，风险可控但不为零。一旦企业版要求合规审查，需要能一键关闭该渠道。

## 界面形态：三个样例

三个样例都建立在**同一套技术底座**上：原生 `NSMenu` 负责点击外部收起、Esc、系统材质、键盘导航，以及打开和收起的动画。因此上一轮那几类问题（点了不收起、材质不对、闪烁、底部死区）在三个样例里都不会出现。

三者的差别在**下拉菜单里放什么、怎么组织**：

| | A 紧凑列表 | B 卡片详情（最接近 CodexBar） | C 渠道分页 |
|---|---|---|---|
| 一句话 | 和系统 Wi-Fi 菜单一样：一个账号一行，扫一眼就够 | 一个账号一张卡片，每个窗口一条进度条，附带重置倒计时 | 顶部用渠道标签切换，下面是该渠道账号的详细卡片 |
| 一个账号占的高度 | 约 44pt | 约 110pt（5h + 周两条） | 约 110pt |
| 8 个账号时 | 约 420pt，无需滚动 | 约 900pt，**需要滚动** | 每页只显示一个渠道的账号，高度可控 |
| 重置时间 | 鼠标悬停时显示子菜单 | 直接显示 | 直接显示 |
| 多窗口（5h / 周） | 一行内放两个小环 | 每个窗口一条完整的进度条 | 每个窗口一条完整的进度条 |
| 适合场景 | S1 扫一眼、S3 找有余量的账号 | S2 开工前确认 | 账号多、渠道多 |
| 代价 | 细节要多点一层才能看到 | 账号多时会变长 | 跨渠道比较要来回切换标签 |

**我的推荐：A + B 混合**
- 默认按 A 列出所有账号，一屏看全。
- 鼠标悬停在某一行时，侧边弹出该账号的 B 卡片（原生子菜单，系统自带的交互）。
- 这和 macOS 自己的 Wi-Fi、蓝牙菜单逻辑一致：主菜单负责扫一眼，子菜单负责看细节。

菜单栏告警沿用你已选定的 **② 红字加粗**。

# 动效与几何问题的复盘（AI HUD，2026-11 上半月）

这份文档只回答四个问题：**出了什么问题、直接原因是什么、本质是什么、下次怎么不犯**。
所有结论都对应本仓库里已存在的回归开关，不是事后感想。

| # | 现象 | 直接原因 | 修法 |

## 二、本质：四类"多源"

### 1. 几何多源 —— 一个视觉矩形有四个副本
窗口 frame、阴影 path、材质层 frame、描边层 frame、内容层 frame，各自被写在不同的地方，
而且**各自默认贴不同的边**：窗口贴顶、材质层贴窗口底、阴影贴窗口底、内容层贴材质层底。
只要高度变化，这四个"边"就会互相打架；表现就是残影、错位、黑环、阴影闪烁。

> 规则：**一个视觉矩形只允许有一个几何源**。目标 `panelRect` 算一次，四层共用；
> 需要"贴哪条边"时显式写出来，不能靠默认。

### 2. 时间多源 —— 同一件事走了两条时间线
内容换页（转场 0.22s）、高度插值（0.18s）、窗口尺寸、阴影重算，各走各的曲线。
两条曲线只要不同相，中间帧就必然出现"两层同时可见"或"内容与面板错位"。

> 规则：**一次状态变化只允许一条时间线**。要么高度动、内容不动；要么内容动、高度不动。
> 不允许"高度动 + 内容也动"。

### 3. 模型值 vs 表现值
`NSView.frame` 是模型值，`CALayer` 的动画是表现值。在 `allowsImplicitAnimation = true`
的上下文里读属性，读到的是**动画开始前**的模型值。用这个值去写另一个视图，就会把它钉在上一帧。
同样地，`v.frame = …` 写在动画组里**不一定**会被插值（实测第一个 16ms 采样 `vY` 已经是 0），
这就是"内容贴底"的根因。

> 规则：**动画期间不读属性，只写常量**；需要跟随的量自己算（逐帧 ticker 里用同一个 `cur`）。

### 4. 验证方式错位（这条最贵）
- 用采样数值代替画面：`mask width 之和恒等于面板宽` 数学上完美，画面却把文字切碎。
- 只验终帧不验中间帧：残影、重影、闪烁全部只在中间帧存在。
- 用 debug 二进制验收：用户打开的是上一版 `.app`，于是"修了但没修"。
- 用多个方案回避决策：把设计判断推给用户，用户每轮都在替我做取舍。

> 规则：**改动必须自己先看中间帧**；交付物必须是重打包的 `.app`（带 build 戳）；
> 一轮只交一个方案。

## 三、下次怎么规避（可直接执行的清单）

### 写代码前
1. 先写下**锚边契约**：面板贴屏幕哪条边、内容贴面板哪条边、阴影等于哪个矩形。三句话，写在文件头。
2. 数一遍有几条几何源。>1 就必须合并，合并不了就写一个函数统一算。

### 写动画时
3. 一条时间线只驱动一件事。高度动画里，内容的尺寸/位置由同一个 `cur` 推出，不用第二条曲线。
4. 窗口尺寸取动画两端里**更大**的那个，动画结束才收；否则较高的一侧会被窗口裁掉。
5. `shadowPath` 永远等于材质层当前矩形，逐帧传 `origin.y`，不要写死 `m`。
6. 动画结束帧只做"收尾一次"，不要重复设 frame + 全量刷新（那一下本身就是闪）。

### 验收时
7. 三个恒等式，必须由 `AIHUD_TRACK=1` 打印并人工核对：
   - `panelTop` 全程不变
   - `contentTop` 全程不变
   - `shadowY − materialY == 0`
8. 中间帧：慢放到 2×，取动画 40% 处的一帧看，不看终帧。
9. 交付：`bundle.sh` → 核对 `AIHUDBuildStamp` → 跑 `.app`（不是 `.build/debug`）→ 截图前 `pkill` 并断言单实例。

### 协作时
10. 一次只给一个方案；给不出来就说明还没想清楚。
11. 先给根因一句话，再给修法，再给一个数字。不要用"已修"结尾。

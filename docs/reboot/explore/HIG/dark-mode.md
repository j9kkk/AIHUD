# Apple HIG（中文）· dark-mode
来源：https://developer.apple.com/cn/design/human-interface-guidelines/dark-mode

深色模式
深色模式是一种系统范围的外观设置，使用深色调色盘为低光环境提供舒适的浏览体验。

在 iOS、iPadOS、macOS 和 Apple tvOS 中，用户经常将深色模式选为默认的界面风格，并通常希望所有 App 和游戏都能贴合他们的个人偏好。在深色模式中，系统会为所有屏幕、视图、菜单和控制使用深色调色盘，并且还可能使用更大的感知对比度，使前景内容在颜色更深的背景上突出显示。

最佳实践

避免提供 App 特定的外观设置。App 特定的外观模式选项会额外增加用户的工作量，因为他们必须调整多项设置才能得到想要的外观。更糟糕的是，用户可能会觉得你的 App 是有问题的，因为 App 没有使用他们选择的系统范围外观。

确保 App 在两种外观模式下都能很好地呈现。除了使用其中一种模式之外，用户还可以选取“自动”外观设置，它会随着一天中条件的变化在浅色和深色外观之间切换，并且可能在 App 运行期间切换。

测试你的内容以确保在两种外观模式下都能保持舒适易读。例如，在“增强对比度”和“降低透明度”打开时（分别打开或同时打开）的深色模式下，你可能会发现深色背景上的深色文本不太容易辨认。你可能还会发现在深色模式下打开“增强对比度”会导致深色文本和深色背景之间的视觉对比度降低。虽然视力好的用户可能仍可以阅读较低对比度的文本，但此类文本对于很多用户而言是难以辨认的。有关指南，请参阅无障碍。

在极少数情况下，可以考虑在界面中只使用深色外观。例如，支持沉浸式观看媒体的 App 始终使用深色外观可能很有意义，因为这种外观可以隐藏用户界面并帮助用户专注于媒体。

深色模式颜色

深色模式下的调色盘包含较暗的背景颜色和较亮的前景颜色。需要注意的是，这些颜色不一定是其对应的浅色颜色的反转：虽然很多颜色是被反转的，但有些颜色则不是。有关更多信息，请参阅规范。

包含适合当前外观的颜色。语义色（如 macOS 中的 labelColor 和 controlColor 或者 iOS 和 iPadOS 中的 separator）会自动适应当前外观。需要自定义颜色时，请在 Xcode 中将“颜色集”素材添加到 App 的素材目录中，并指定颜色的亮和暗变体。避免使用无法自适应的硬编码颜色值或颜色。

力求所有外观都有足够的颜色对比度。使用系统定义的颜色可以帮助你在前景和背景内容之间实现良好的对比度。至少要确保颜色之间的对比度不低于 4.5:1。对于自定义前景色和背景色，应尽量将对比度设为 7:1，尤其是在小文本中。这个比例可以确保前景内容突出显示在背景上，并使内容遵循推荐的无障碍指南。

柔化白色背景的颜色。如果显示的内容图像包含白色背景，应考虑略微调暗图像，以防止背景在周围的深色模式环境中发光。

图标和图像

系统使用可自动适应深色模式的 SF 符号以及针对浅色和深色外观优化的全彩图像。

尽可能使用 SF 符号。使用动态颜色来着色或者加入虚化效果时，符号在两种外观模式下都不会出现什么问题。有关指南，请参阅颜色。

如有必要，为浅色和深色外观设计单独的界面图标。例如，描绘满月的图标可能需要微妙的深色轮廓来与浅色背景形成良好的对比，但当它在深色背景上显示时，轮廓就不需要了。同样地，表示一滴油的图标可能需要细边框，以便在深色背景下可以看到边缘。

为标签使用系统提供的标签颜色。一级、二级、三级和四级标签颜色会自动适应浅色和深色外观。

平台考量因素

无针对 Apple tvOS 的额外考量因素。visionOS 或 watchOS 不支持深色模式。

iOS、iPadOS

在深色模式下，当一个深色界面叠放在另一个上面时，系统会使用两组背景颜色（称为基本色和提升色）来增强深度感知。基本色较暗，使得背景界面看起来像是在后退；提升色较亮，使得前景界面看起来像是在前进。

浅色

优先使用系统背景颜色。深色模式是动态的，这意味着当界面位于前景时，背景颜色会自动从基本色变为提升色，例如弹出窗口或模态表单。系统还会使用提升的背景颜色在多任务环境中提供 App 之间的视觉分离，并在多窗口环境中提供窗口之间的视觉分离。使用自定义背景颜色会让用户更难以感知这些系统提供的视觉差异。

macOS

当用户在“通用”设置中选取石墨色作为强调色时，macOS 会让窗口背景从当前桌面图片中提取颜色。结果称为桌面着色，它是一种微妙的效果，可让窗口与其周围的内容更和谐地融合在一起。

适当的时候，在自定义组件背景中加入一些透明度。透明度可让组件在桌面着色生效时从窗口背景中提取颜色，从而创造出一种即使桌面图片发生变化也可以保持的视觉和谐感。为了帮助实现这种和谐感，请只给背景或外框可见的自定义组件添加透明度，并且仅当组件处于中性状态（例如不使用颜色的状态）时添加透明度。当组件处于使用颜色的状态时不应添加透明度，因为这样做会导致窗口背景调整到桌面的其他位置或者桌面图片发生变化时，组件的颜色发生波动。

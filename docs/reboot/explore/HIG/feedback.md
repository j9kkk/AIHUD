# Apple HIG（中文）· feedback
来源：https://developer.apple.com/cn/design/human-interface-guidelines/feedback

反馈
反馈可帮助用户了解正在进行的操作，发现下一步可执行的操作，理解操作的结果，以及避免错误。

当用户与 App 或游戏交互时，提供清晰且一致的反馈可让体验更直观，并鼓励用户更深入探索。反馈可以传达多种不同信息，例如：

内容的当前状态

重要任务或操作是成功还是失败

对可能产生负面后果操作的警告

纠正错误或有问题情况的机会

最有效的反馈往往是将信息的重要性与其传递方式相匹配。例如，被动显示状态信息以供用户按需查看通常非常适用。相比之下，数据可能丢失的警告则需要打断用户，以便他们有机会避免该问题。

最佳实践

确保所有反馈都可访问。使用多种方式提供反馈时，你的受众会更多并让他们有机会以合适的方式接收反馈。例如，当你使用颜色、文本、声音和触感反馈提供反馈时，用户无论是否静音设备、注视屏幕或使用“旁白”都能接收反馈。（有关提供触感反馈的指南，请参阅提供触感反馈。）

考虑在界面中整合状态反馈。当状态反馈在其描述的项目附近可用时，用户无需操作或离开当前环境即可获取重要信息。例如，iOS 和 iPadOS 中的“邮件”描述最近的更新，并在邮箱屏幕的工具栏中显示未读邮件的数量，使信息不引人注目，但便于用户在感兴趣时查看。

使用提醒传递理想情况下可操作的重要信息。按照设计，提醒会中断当前环境，因此信息的重要性需要与中断的级别相匹配。如果提醒使用过于频繁或者传递不重要的信息，那么其可能会失去相应作用。有关指南，请参阅提醒。

当用户启动的任务可能导致非预期且不可逆转的数据丢失时，向他们发出警告。相反，当数据丢失是用户操作的预期结果时，不用发出警告。例如，访达不会在用户每次丢弃文件时发出警告，因为删除文件是预期结果。

根据情况，确认重要操作或任务已经完成。例如，用户乐于接收确认 Apple Pay 交易成功的反馈。一般来说，最好将此类确认用于足够重要的活动，因为用户通常期望其操作或任务成功，只有在不成功时才需要知道。

无法执行命令时，告知用户并帮助他们了解原因。例如，如果用户在没有指定目的地的情况下请求路线，“地图”就会告知用户无法提供往返同一位置的路线。

平台考量因素

无针对 iOS、iPadOS、macOS、Apple tvOS 或 visionOS 的额外考量因素。

watchOS

避免在 watchOS App 中显示不确定的进度指示符，如加载指示符。动画指示符会让用户认为他们需要继续关注屏幕，这不是一种好的用户体验。为了提供更好的用户体验，让用户相信在进度完成时会收到通知。

# MVP A / MVP B 验收记录（第二版 · 按原型逐像素重做）

上一版的问题：两个屏幕由子智能体各自发挥，字号、间距、颜色、图标全是估的，和原型对不上；
面板切换二级页时 `layout` 用 `f.origin.y = f.maxY - h` 反复推算顶边，`setFrame` 改尺寸会让 `maxY` 漂移，
于是每切一次页面就往下滚一点，最后跑出屏幕。

本版的做法：先用浏览器把 `p11.html` / `p12.html` 里每个元素的
`getBoundingClientRect` + `getComputedStyle` 全量导出（`measure-p11.json` / `measure-p12.json`），
Swift 端的每个坐标、字号、颜色都从这份数据抄，不再凭感觉。

## 页面切换时的位移：两个独立根因（2026-11-01 二次排查）

### 根因 1：内容层高度被算了两次（内容掉到底部、上方留一条空带）

内容视图用 `autoresizingMask = [.width, .height]`，而 `place()` 又显式设了 `view.frame = (0,0,w,h)`。
`panel.setFrame` 改高度时，autoresizing 会按「父视图变化量」再改一次子视图高度：

```
list 226 → grid 352.5：先设成 352.5，窗口 +127 又加一次 → 内容层 479.5
grid 352.5 → list 225.5：先设成 225.5，窗口 -127 再减一次 → 内容层 98.5
```

内容层比窗口高/矮，又按左下角定位，画面上就是内容整体往下掉一段，顶部留空带。

修法：`autoresizingMask = []`（尺寸完全由 `place()` 决定），并且**先定窗口、再把内容层贴到顶**：

```swift
panel.setFrame(f, display: true)
v.frame = NSRect(x: 0, y: effect.bounds.height - h, width: w, height: h)  // y 从底边量起 = 贴顶
```

动画时窗口与内容层在同一个 `NSAnimationContext` 里插值：先把内容顶边钉在*当前*窗口顶边
（`y = curSuper - h`），再一起过渡到 `(0,0,w,h)`，两段都满足 `y(t) = superH(t) - h(t)`，顶边全程不动。

实测（`AIHUD_SWITCH_TEST=1`，每次切换后等 250ms 再量）：

```
A: open 353/352.5 → detail 271/270.5 → pop 353/352.5
B: list 226/225.5 → grid 353/352.5 → back 226/225.5 → detail 236/235.5 → pop 226/225.5
（前一个数 = 窗口高，后一个 = 内容层高，期望高度与内容层一致）
```

### 根因 2：锚点读到了假的菜单栏按钮矩形（面板横向飞到屏幕中间）

`anchor()` 每次都读 `status.button.window` 的屏幕矩形。面板打开后这个矩形会变：

```
18:32:47  btn={{0,-11},{32,22}}        → 未布局，判为假值，用兜底锚点 1496/919 ✓
18:32:49  btn={{882,954.5},{79,22}}    → 面板一打开就变成这个值 → 锚点算成 961/943 ✗
```

于是第二次切换后 `panel.origin.x` 从 1144 变成 609，看起来就是「面板不可控地位移到屏幕外」。

修法：锚点**只在打开面板时取一次并缓存**，打开期间不再读按钮；屏幕参数变化（分辨率/显示器）
时缓存失效。同时给矩形加合法性判断（y 必须在菜单栏带内、宽度 16–400），顶边再夹一层
`min(top, visibleFrame.maxY - 8)`，避免压到菜单栏。

实测（`AIHUD_DEBUG=1 AIHUD_SWITCH_LIVE=1`，2 秒后切视图、4 秒后切回）：

```
PLACE anchor=(1496,919) → 1144/693.5 (226)
PLACE anchor=(1496,919) → 1144/566.5 (352.5)
PLACE anchor=(1496,919) → 1144/693.5 (225.5)
```

锚点三次一致，x 恒为 1144，顶边恒为 919。真窗口截图 `live-list.png` 复核：内容贴顶、底部紧贴页脚。

回归入口：
```bash
AIHUD_SWITCH_TEST=1 .build/debug/MVPB      # 打印 窗口高 / 内容层高 / 期望高
AIHUD_ANIM_TEST=1   .build/debug/MVPB      # 动画期间连续采样（读呈现层）
AIHUD_SWITCH_LIVE=1 .build/debug/MVPB      # 真窗口，2s/4s 各切一次，供截图
AIHUD_GEOM_TEST=25  .build/debug/MVPA      # 反复开关 + 进二级，查稀疏度
```

## 面板位移：回归测试

`Shell.place()` 现在是唯一布局入口，每次布局都从状态栏按钮重新算锚点：

```swift
let a = anchor()                       // 右边缘 = 图标右边缘，顶边 = 图标下沿 - 6
var f = NSRect(x: a.right - w, y: a.top - h, width: w, height: h)
f.origin.y = max(vf.minY + 8, min(f.origin.y, vf.maxY - h - 8))
```

顶边永远由锚点算出，不再从上一帧的 `maxY` 推，所以不可能累计漂移；越界一律夹回可见区域。

回归测试（`AIHUD_GEOM_TEST=N` 反复「打开 → 进二级 → 返回 → 关闭」N 轮）：

```bash
AIHUD_DEMO=1 AIHUD_GEOM_TEST=40 .build/debug/MVPA    # topSpread=0.00 rightSpread=0.00 offscreen=0
AIHUD_DEMO=issue AIHUD_GEOM_TEST=40 .build/debug/MVPB # 同上
```

实际帧：一级 `{1144,566,352,353}` → 二级 `{1144,648,352,271}` → 返回 `{1144,566,352,353}`，
三级顶边都是 919、右边缘都是 1496，没有一次越界。


## 质感对齐：字体、内间距、阴影、面板透明度（2026-11-01 第三轮）

### 字体：粗细按 CSS 值逐项核对，问题在渲染不在字号

原型里的字体契约（从 `getComputedStyle` 逐节点统计，括号内是出现次数）：

| 角色 | 原型 | 实现 |
|---|---|---|
| 面板标题 / 模块名 / 时间轴倒计时 / 告警标题 | 13px **600** 系统（13） | `Theme.f13b` 系统 semibold ✅ |
| 大数值 | 17px **600** SF Pro **Rounded**（8） | `Theme.f17b` rounded 17/600 ✅ |
| 数值后的 `%` | 13px **600** Rounded（6） | `Theme.rounded13` ✅ |
| 圆环内数值 | 15px **600** Rounded（p12，3） | `Theme.f15b` rounded 15/600 ✅ |
| 窗口名 / 命令行 / 正文 | 13px 400（13–16） | `Theme.f13` ✅ |
| 重置时间 / 说明 | 11px 400（14） | `Theme.f11` ✅ |
| 套餐徽章 | 10px 400（10） | `Theme.f10` ✅ |

字号字重是对的，真正偏粗的是**栅格化**：AppKit 在图层里默认开「字体加粗」平滑，
2× 下同一段 11/400 的笔画比浏览器粗整整 1 像素。实测笔画中位宽度（2×，同一行文字扫描）：

| | 原型 | 修复前 | 修复后 |
|---|---|---|---|
| 11/400 脚注 | 2.0 px | **3.0 px** | 2.0 px |
| 13/600 模块名 | 3.0 px | 4.0 px | 3.0 px |

修法：每次绘制前 `cg.setShouldSmoothFonts(false)` + `setShouldAntialias(true)`。
注意必须每帧设，CGContext 每帧都是新的（写成全局只设一次等于没设）。

| 容器 | 原型 | 实现 |
|---|---|---|

| 模块文字左内缩 | 12 + 文本 bearing ≈ 26pt 落墨 | 24.5pt 落墨（差 1.5pt，未改，怕破坏整列对齐） |

### 阴影：原来是系统那层薄影，现在按原型三层重做

- 原型：`0 0 0 .5px rgba(0,0,0,.6)` + `0 2px 8px rgba(0,0,0,.28)` + `0 20px 54px rgba(0,0,0,.48)`
- 之前：`panel.hasShadow = true`，只有系统给的 1 层，且边界一硬就没了
- 现在：窗口比面板四周各留 26pt，`host.layer.shadowPath` 画在留出的一圈里
  （半径 27、偏移 (0,-10)、不透明度 .48），外加 0.5pt 黑色外描边 + 0.5pt `white .14` 内描边。
  实测（深色桌面，亮度 15）：面板下沿外 10.2 → 30pt 外 15.0；上沿外 12.9 → 15.0。
- 陷阱：`layer.borderWidth` 画在 host 边界（=窗口），会把黑边画到窗口外框上，必须单独用一个
  和面板同尺寸的 `rim` 视图；`effect.frame.y` 要从 `m` 起（不是 0），否则面板贴窗口底、上下边距不对称。

### 面板透明度

- 原型：`background: rgba(30,30,32,.68)` + `backdrop-filter: blur(40px) saturate(1.9)`
- 实现：`NSVisualEffectView(material: .hudWindow, blendingMode: .behindWindow, state: .active)`，
  圆角 14，没有额外叠加 tint（材料本身就带 0.6–0.7 的黑度）。实测面板内亮度 30.4，桌面 15，
  即约 50% 压暗 + 模糊，与原型 0.68 的暗度接近。
- 未做：原型那层 `saturate(1.9)` 的色彩增强，`NSVisualEffectView` 没有对应参数，
  只能自己用 `CIFilter` 做 blur+saturate 再贴图，成本高，暂不实现（列在待拍板清单里）。

## 动效（2026-11-01 第四轮）

之前只有一种动画：改窗口高度 → 内容跟着"上下滑"。现在按用途拆成五种，
并加了 `TWEEN_TEST` / `SWITCH_TEST`（打印 `animationKeys`）两个可复现的验收入口。

| 场景 | 实现 | 参数 |
|---|---|---|
| 面板出现 | alpha 0→1 + 内容层 `scale 0.98→1` + 上移 2pt | fade 0.18s，spring damping 22 / stiffness 260 |
| 面板收起 | alpha 1→0（120ms）后 orderOut | — |
| 一级 ↔ 二级 | `CATransition(.push)`，进 `.fromRight`、退 `.fromLeft` | 0.22s easeInEaseOut |
| 列表 ↔ 圆环 | `CATransition(.fade)` + `scale 0.98→1`（morph） | fade 0.16s，spring 0.28s |
| 刷新中 | 刷新图标按 `spinAngle` 旋转，60fps ticker 驱动 | 1.6 圈/秒 |
| 数值变化 | 旧值淡出并上移 2pt，新值淡入；圆环/进度条同步补间 | 0.26s，easeOutBack（末段轻微过冲） |

技术要点：

- **窗口不吃 spring**：`NSWindow.animator().setFrame` 只认 timing function，所以窗口高度用 easeInEaseOut，
  内容层的缩放/位移用 `CASpringAnimation`；两者同 duration，顶边全程不动（沿用上一轮那套约束）。
- **缩放不改 anchorPoint**：改 anchor 会和显式 `frame` 打架，改用
  `translate(center) · scale · translate(-center)` 组合出"绕中心缩放"。
- **数值补间只在自己身上**：`TweenStore` 按 key 存 from/to/start，`draw` 时取插值，
  没有额外图层，也不影响离屏快照（首次出现不做动画）。
- **尊重「减弱动态效果」**：`NSWorkspace.shared.accessibilityDisplayShouldReduceMotion` 为真时，
  转场只保留 fade、缩放/位移全关（HIG 硬要求）。

实测（`AIHUD_TWEEN_TEST=1`，把各窗口剩余比例 ×0.5 后连采 6 次）：

```
A: 0.519 → 0.315 → 0.241 → 0.240 → 0.259 → 0.260   （目标 0.26，末段轻微过冲后落定）
B: 0.517 → 0.314 → 0.240 → 0.239 → 0.258 → 0.260
```

`AIHUD_SWITCH_TEST=1` 里能看到转场确实挂上了：

```
open-list anim=[scaleIn,riseIn]        ← 出现动画
detail    anim=[position,transition,scaleIn]   ← push 转场
pop       anim=[transition,scaleIn]            ← 返回转场
```


### 页面切换的高度抖动（2026-11-01 第五轮）

现象：横向推入的同时窗口高度也在插值，旧内容被一点点裁掉、面板底边同时上移，两个方向的动作叠加看起来就是"抖"。

原因：`place(animated: true)` 在转场时仍然走了高度动画分支（0.18s easeInEaseOut），
而 `CATransition` 的 push 是 0.22s，两条曲线不同步，裁切边和滑动边各自跑。

修法：**转场期间高度直接到位**，不参与插值。`place()` 里判断 `screen.pendingTransition != nil`，
命中就走非动画分支，只保留横向 push；高度不再是第二个动作，眼睛只跟一条轨迹。

实测（`AIHUD_SWITCH_TEST` 现在打印切换瞬间的窗口高度）：

```
grid    immediateH=278.0     detail  immediateH=288.0
back    immediateH=405.0     pop     immediateH=405.0
```

切换调用返回时窗口已经在目标高度，`animationKeys` 里也只剩 `transition`（+ 残留的出现动画），
不再有窗口 frame 的插值。

其余高度变化（刷新后行数变了）仍然走 0.18s 动画——那种场景没有横向位移，不会打架。


### 切页改成交叉溶解（2026-11-01 第六轮）

横向推入在高度差 120pt 的面板里，无论怎么调都会和高度变化抢注意力，所以换掉：

- 旧页拍快照（`bitmapImageRepForCachingDisplay`）盖在原视图上，上移 8pt、缩到 0.99、淡出；
- 新页从下方 8pt 上来、0.99→1、淡入；
- 窗口高度用同一个 0.24s 同步收放——交叉溶解把裁切边盖住了，不会再有第二个方向的运动；
- 列表↔圆环用同一条路径，位移收到 4pt、缩放 0.985（幅度更小，因为是同级切换）。

验证（`AIHUD_DISSOLVE_TEST`，采样两层的呈现层不透明度）：

```
old=0.92 new=0.31 | old=0.61 new=0.61 | old=0.24 new=0.84 | old=0.02 new=0.98 | old 移除 new=1.00
```

两个透明度此消彼长，0.24s 后快照层移除。`GEOM_TEST` / `SWITCH_TEST` / `TWEEN_TEST` 仍然全绿。

已知取舍：方向感弱了（原来靠左右推入表达"进入下一层"）。如果要补回来，
可以在溶解的同时给新内容一个 1.5° 的轻微透视或 2pt 的水平位移，但幅度一大又会回到"抖"的老问题。


### 闪烁根因 + 四套可切换方案（2026-11-01 第七轮）

**闪烁根因**：快照视图当时是**内容视图的子视图**，而我又给父层做了 `opacity 0→1`。
两层透明度相乘，中段内容只剩 0.61×0.61 ≈ 0.37，材质透出来 → 背景像白炽灯闪一下。
抽样证实：修复前中段 `old=0.61 new=0.61`，合成覆盖率只有 0.37。

修法：快照挂到**材质层 `effect`** 上（与内容层是兄弟），两层各自独立淡入淡出，不互相乘。
另外给快照的模型值也置 0（否则动画一结束图层会弹回不透明，末尾再闪一下）。

修复后（`AIHUD_DISSOLVE_TEST` 采样旧页/新页呈现层不透明度 + 合成覆盖率）：

```
style 0  old=0.92 new=0.31 cover=0.94 | old=0.62 new=0.61 cover=0.85 | old=0.24 new=0.84 cover=0.88 | cover=0.98 | cover=1.00
style 1  同上（纯溶解，无位移）
style 2  同上（从卡片钻入）
style 3  old=0.97 new=0.19 cover=0.98 | ... cover=0.85 ... 0.91 | 1.00
style 4  old=0.81 new=0.45 cover=0.89 | ... cover=0.86 ... 0.99 | 1.00
```

覆盖率全程 ≥ 0.85（修复前会掉到 0.37）。

**五套方案**（菜单「过渡方案」里可切，或 `AIHUD_TRANSITION=0…4`）：

| # | 名称 | 做法 | 高度时机 |
|---|---|---|---|
| 0 | 溶解+位移 | 旧页上移 8pt 淡出，新页从下方 8pt 淡入，缩放 0.99→1 | 与淡入同步 0.24s |
| 1 | 纯交叉溶解 | 只淡入淡出，无位移无缩放 | 同步 0.24s |
| 2 | 从卡片钻入 | 新页从被点卡片的中心放大 0.94→1，旧页快速淡出并微放大 | 同步 0.24s |
| 3 | 先收高度再淡入 | 高度瞬变 → 30ms 后 0.18s 淡入 | 先变 |
| 4 | 保持高度后收边 | 按两页较高者撑住 → 0.18s 淡入 → 0.16s 收边 | 后变 |

切换方式：状态栏图标右键 → 过渡方案 → 选一个；选择存 `AIHUD.transition`，下次启动沿用。

### 没做的

- **narrative 连续性**：列表行 → 圆环格 的"同一个数飞过去"（matched geometry），
  需要快照 + 手工插值，复杂度高，暂不做。
- **SF Symbols 的效果类 API**（`NSSymbolRotateEffect` 等）没直接用：我们的图标是
  `NSGraphicsContext` 里画的 SF Symbol，不是 `NSImageView`，所以用旋转角度自己驱动；
  视觉等价，且不引入额外子视图。
- **刷新时的环"弹一下"**只在数值变化时触发；如果刷新拿到的数值没变，环不动（符合预期）。

## 七、切换时内容上下滑（2026-11-01 第七轮）

### 现象
三档视图（列表 / 圆环 / 模块）互相切换时，"滑入"方向不固定：有的从上往下、有的从下往上。

### 根因
面板**顶边固定、底边在动**，而内容层是**贴底**放的（`v.frame = (0, 0, w, 新高度)`），
所以新旧高度差多少，内容就整体错位多少：

- 变高（圆环 225.5 → 模块 358.5，差 133）：内容顶边跑到面板上沿**外侧 133pt**，被窗口裁掉上半，
  画面上先看到页面下半，再随着面板变高整个下来 —— 读作"从上滑入"。
- 变矮（358.5 → 225.5）：内容顶边落在面板顶部**内侧**，内容从下方被切 —— 读作"从下滑入"。

方向完全由"新高度比旧高度大还是小"决定，所以看起来时上时下。

证据（修复前 `AIHUD_TRACK=1` 采样，面板顶边 919 恒定）：
`contentTop=1051.5 → 918.5` 跟随高度从 225.5 长到 358.5 —— 内容顶边在动。

### 修法
1. 内容层高度**永远等于面板当前高度**（`v.frame = (0, 0, w, cur)`），顶边天然对齐，不再有高度差。
2. 高度变化改成显式逐帧驱动（120Hz Timer，easeInOutQuad 0.20s），四层（窗口 / 材质 / 描边 / 内容）同一循环里写；
   窗口一次性设到目标尺寸（窗口四周 26pt 是透明阴影边距），只动材质层与内容层，避免和窗口服务器抢帧。
3. 绘制本来就是"从顶往下"的绝对坐标，因此内容增长=向下展开、收缩=从底部收起，中间没有任何整体位移。

### 验证
`contentTop` 在整段动画里恒定，两个方向都是：

| 方向 | 面板顶边 | 面板底边 | 内容顶边 |
|---|---|---|---|
| 358.5 → 296.5 | 919.0 → 919.0 | 622 → 622* | 918.5 → 918.5 |
| 296.5 → 225.5 | 919.0 | 693 | 918.5 |

（*窗口目标尺寸一次到位，面板底边由材质层动画，落在窗口内）

回归：`GEOM topSpread=0.00 rightSpread=0.00 offscreen=0`（demo/issue 各 10 轮）；
三档切换后 `effectH == contentH == expect`。


## 八、切换时面板周围阴影闪烁（2026-11-02 第八轮）

### 根因（三条叠加）
1. **阴影路径锚在窗口底边**：`updateShadowPath` 固定用 `CGRect(x: m, y: m, w: h)`，
   而窗口是**顶边钉住**的、面板在该窗口里是自上而下伸缩 → 动画期间阴影矩形和面板矩形在垂直方向错开 `(winH − cur)`。
   错开时阴影被窗口裁掉，面板下沿"没有影子"；动画结束窗口一收，影子突然回来 —— 看起来就是闪。
2. **窗口尺寸取的是目标高度**：变矮时面板在动画前段比窗口高，下沿被窗口硬裁，
   玻璃面板底边的圆角被切掉，收尾那帧再补齐 → 又闪一下。
3. **收尾重复刷新**：`p >= 1` 时重设了一遍相同的 frame 并调用 `refreshChrome()`（里面还有 `panel.invalidateShadow()`），
   多触发一次全量重绘。

### 修法
- `updateShadowPath(..., y:)` 增加 y 参数，**每帧传面板当前的下沿** `pr.origin.y`；静止时传 `m`。
- 动画期间窗口一次性设到 `max(oldH, h)`（两段里更高的那个），动画中不动窗口；结束帧再收到目标高度（此时外部只是透明阴影边距，不可见）。
- 结束帧删掉重复的 frame 设置与 `refreshChrome()`；`refreshChrome()` 里去掉 `panel.invalidateShadow()`。

### 验证（`AIHUD_TRACK=1`，120Hz 采样）
| 量 | 修复前 | 修复后 |
|---|---|---|
| `shadowY − effectY` | 最大 62（随后被裁） | 全程 **0.0** |
| `shadowH − effH` | 相等但 y 错位 | 全程相等 |
| 面板底边越界 | 最矮方向 −34.3（被窗口裁） | 最小 26（始终在窗口内） |

实机 6 帧（列表→圆环、圆环→模块）复核：影子单层、贴边、圆角连续，无分离、无黑环。
交付包 `build=20261102-000951`。

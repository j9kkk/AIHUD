## 0. 上一轮为什么失败（重启的前提）

| 现象 | 根因 |
|---|---|
| 「功能大部分不可用」 | **先做界面、后打通数据**。到最后只有 WorkBuddy 真实读到过额度（1,857 / 13,328）；Claude 卡在换 token（429 / 流程卡死），Codex 导入的凭据过期了，之后再也没读到过。 |
| 「视觉不符合需求」 | 视觉标准来自自写的原型和规范，**没有在一开始和你对齐参照物**；还重写了三遍（Tauri WebView → Tauri 改版 → Swift AppKit），每遍都在手工重做系统本来就提供的东西：材质、收起、转场、布局。 |
| 范围失控 | 一个只是「看一眼额度」的工具，写出了 44 屏原型、2246 行规格、300 条测试，却没有一条「真实账号连续用一周」的验收。 |

**重启原则**：真实数据先打通，界面后做；系统控件能用就不自己画；成功判据必须能在真机上验证。

## 1. 目标用户

**主用户：你本人**（及与你同类的人）。

- 个人开发者，**同时订阅多个 AI 编程服务**，并且**同一服务有多个账号**（例如 `joker-claude`、Codex Plus、WorkBuddy 国内站付费）。
- 在 macOS 上全天开着 Claude Code、Codex、WorkBuddy 等工具，额度按 5 小时和每周两个窗口滚动，或者按积分包扣减。
- 中文用户；WorkBuddy 用国内站，Claude 和 Codex 走代理（本机代理 127.0.0.1:7897）。

**不是**目标用户：团队管理员（看组织账单）、只用 API Key 按量付费的人（那是成本报表，不是额度）。

## 2. 使用场景（按频率排序）

| # | 场景 | 用户此刻想知道的 | 能接受的打扰程度 |
|---|---|---|---|
| S1 | **余光扫一眼**：写代码时瞄一眼菜单栏 | 有没有哪个账号快用完了 | 零：不点击、不弹窗 |
| S2 | **开工前确认**：要开始一个大任务（比如长时间跑 agent） | 用哪个账号？它的 5 小时和周额度各还剩多少？什么时候重置？ | 点一下，1 秒内看完 |
| S3 | **撞线了**：某个工具报额度用尽 | 哪个账号还有余量，多久能恢复 | 点一下 |
| S4 | **快用完时被提醒**：低于阈值或刚刚耗尽 | 哪个账号、剩多少 | 一条系统通知，同一状态只提醒一次 |
| S5 | **偶尔维护**：加账号、登录失效后重新授权、删账号 | 怎么在 1 分钟内弄好 | 可以打开一个正常窗口 |

## 3. 核心动作（只有这些）

| 动作 | 触发方式 | 预期结果 |
|---|---|---|
| A1 看总览 | 菜单栏图标常驻 | 显示**最紧张的那个账号**的剩余百分比；低于 20% 时变红 |
| A2 看明细 | 点击菜单栏图标 | 列出所有账号：别名 · 套餐等级 · 每个窗口的剩余和重置时间（积分制账号显示剩余积分和到期时间） |
| A3 收起 | 点击面板外任意位置 / 再点一次图标 / Esc | 面板立即消失，行为与系统菜单一致 |
| A4 刷新 | 自动刷新（默认 5 分钟），也可以手动点刷新 | 数字更新；读取失败时明确显示「读不到」，**不显示任何猜测的数字** |
| A5 加账号 | 菜单「添加账号…」→ 选择渠道 → 浏览器授权 → **自动回到本机**（不需要粘贴码） | 授权完成后 60 秒内出现真实数字 |
| A6 修复失效账号 | 失效账号旁边显示「重新授权」 | 走同一套授权流程，保留别名 |
| A7 删除 / 隐藏账号 | 在设置里操作 | 删除时一并清除钥匙串中的凭据 |

渠道范围：**Claude（订阅）、Codex（ChatGPT 订阅）、WorkBuddy（国内站 + 国际站）**。

## 7. 核心流程（方案 3）

三个界面各管一件事：**桌面组件**负责常驻查看，**菜单栏**负责告警，**系统通知**负责状态变化。

### F1 添加账号（一次性）

1. 菜单「添加账号…」→ 选渠道。
2. 浏览器打开官方登录页。用户登录后浏览器**自动跳回本机**，不需要粘贴授权码：
   - Claude：`localhost:54545/callback`（PKCE）
   - Codex：`localhost:1455/auth/callback`（PKCE）
   - WorkBuddy：登录状态轮询（`auth/state` → `auth/token`），之后读取账号的 uid 和企业 ID
3. 凭据只写入 AI HUD 自己的钥匙串条目；账号列表（别名、渠道、脱敏身份）写入本地文件，**文件里不含凭据**。
4. 写入后立即执行一次 F2。授权完成到组件出现真实数字 ≤ 60 秒（判据 D1）。

### F2 取数（每个账号独立，互不阻塞）

1. 从钥匙串读凭据。
2. 凭据快过期就先续期：Claude 提前 4 小时，Codex 提前 96 小时，WorkBuddy 在访问令牌或续期令牌任一个 30 分钟内到期时续。续期时网络失败**不重试**，因为 refresh token 只能用一次。
3. 请求额度接口，解析成统一读数：窗口剩余比例和重置时间，或者剩余积分和总积分。
4. 结果只有四种：**正常 / 需重新授权 / 限流中 / 读不到**。只有「正常」显示数字。

### F3 显示

| 界面 | 平时 | 有账号低于 20% | 有账号需重新授权 |
|---|---|---|---|
| 桌面组件（大号） | 每个账号一块：窗口名、等长进度条、剩余和重置时间 | 该账号的数字和进度条变红 | 虚线占位加「需重新授权」，不显示数字 |
| 菜单栏 | 只有图标 | 图标旁边显示最低的百分比，红字加粗 | 图标带感叹号 |
| 菜单 | 立即刷新 / 添加账号… / 设置… / 退出 | 顶部列出告警的账号 | 顶部出现「重新授权「别名」…」 |

### F4 刷新

- 自动刷新：每 5 分钟一次（切片阶段不做）。
- 手动刷新：菜单「立即刷新 ⌘R」。所有账号并发刷新，组件右上角的更新时间随之变化；刷新期间保留旧数字，不闪烁。

### F5 通知（切片阶段不做）

同一状态只通知一次：低于阈值、刚耗尽、刚恢复。

## 8. 垂直切片 V0（当前阶段）

**目的**：在搭建架构、做设置页之前，先证明真实数据能从三个渠道的 API 走到屏幕上。

| 做 | 不做 |
|---|---|
| 三个渠道各走一次真实授权，凭据存入钥匙串 | 设置页、账号管理、改名、删除 |
| 从真实 API 各取一次额度 | 自动刷新、通知、阈值配置 |
| 大号桌面组件显示真实数据 | 小号和中号组件、WidgetKit |
| 菜单栏图标和数字 + 菜单「立即刷新」 | 分层架构、协议对照测试（下一阶段） |
| 凭据过期时续期一次（只按过期时间触发） | 提前续期的完整策略 |

**验收**：
1. 三个渠道的真实数字出现在桌面组件上，截图。
2. 点「立即刷新」后，更新时间变化，数字是新取的（看日志里的请求记录）。
3. 日志和本地文件中搜不到任何凭据明文。
